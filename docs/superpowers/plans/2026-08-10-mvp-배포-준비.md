# MVP 배포 준비 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` (권장) 또는 `superpowers:executing-plans` 로 태스크 단위 실행. 각 스텝은 체크박스(`- [ ]`)로 추적한다.

**설계 원본:** `docs/superpowers/specs/2026-08-10-mvp-배포-design.md`

**Goal:** 배포하면 즉시 막히는 결함 6개(B1~B6)를 없애고, EC2 1대 + Vercel 로 실제 배포할 수 있는 스크립트·CI/CD·운영 문서를 갖춘다.

**Architecture:** 백엔드는 `demo` 프로파일(= prod 기반 + 데모 시드 + Mock 위치 소스)로 EC2 단일 컨테이너에서 돌고, Postgres·Redis·Kafka·nginx 가 같은 호스트에 컨테이너로 붙는다. GitHub Actions 가 이미지를 빌드해 ECR 에 올리고 SSM Send Command 로 EC2 에 배포한다. Flutter Web 은 Actions 에서 빌드해 Vercel 에 prebuilt 로 올린다.

**Tech Stack:** Spring Boot 4.1.0 / Java 25 / Gradle · Flyway · Docker Compose v2 · nginx + certbot · GitHub Actions(OIDC) · AWS EC2·ECR·S3·SSM · Vercel · Flutter

## Global Constraints

- 패키지 루트는 `src.backend`. 새 클래스는 반드시 이 하위에 둔다(컴포넌트 스캔 범위).
- 웹 스타터는 신형 아티팩트명 `spring-boot-starter-webmvc` 계열. 구 `spring-boot-starter-web` 을 쓰지 않는다.
- 스키마는 Flyway 가 관리하고 `ddl-auto: validate`. **`V1__init_schema.sql` 수정 금지**, 새 컬럼은 `db/migration/V{n}__설명.sql` 추가.
- service·repository 는 "구현이 바뀔 가능성"이 있을 때만 `spec`/`impl` 로 분리한다. `package-info.java` 를 두지 않는다.
- **백엔드 인스턴스는 1개로 고정.** `@Scheduled` 4개 중복 실행·`InMemoryBusLocationRepository`·WebSocket 세션 로컬 보관 때문. compose 에 `replicas` 를 넣지 않는다.
- `@SpringBootTest` 계열 테스트는 **Postgres·Redis·Kafka 가 떠 있어야** 통과한다. Docker 가 꺼져 있어 실패하면 코드 결함이 아니라 환경 문제로 분류한다. 사용자에게 먼저 기동을 요청한다.
- 산출 문서(`.md`)는 개조식 체언 종결을 쓴다(`~였음`·`~있었음` 금지).
- 사람용 HTML 문서는 **명시적 요청이 있을 때만** 만들거나 고친다.
- 작업 브랜치: `feat/mvp-deployment` (현재 `feat/mvp-expansion-backend` 에서 분기).

```java
import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;

 * 배포 성공 판정에 쓰는 헬스 엔드포인트 계약을 고정한다.

        mockMvc.perform(get("/actuator/health"))
                .andExpect(jsonPath("$.components").doesNotExist());

    @DisplayName("health 외 액추에이터 엔드포인트는 외부에서 읽을 수 없다")
    void otherEndpointsAreNotReadable() throws Exception {
        int status = mockMvc.perform(get("/actuator/env"))
                .andReturn().getResponse().getStatus();
        // 노출 목록에 없어 매핑되지 않거나(404), 시큐리티가 먼저 막는다(401).
        // 어느 쪽이든 "읽히지 않는다"가 지켜야 할 계약이다.

    }
```

```dockerfile
    && rm -rf /var/lib/apt/lists/*
COPY --from=build /app/build/libs/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## Task 2: 시드 비밀번호 해시를 Flyway placeholder 로 외부화 (B1 준비)

**Files:**
- Modify: `backend/src/main/resources/db/migration-local/V2__seed_data.sql:16`
- Modify: `backend/src/main/resources/application.yml` (local 프로파일 섹션)

**Interfaces:**
- Consumes: 없음
- Produces: Flyway placeholder `seedPasswordHash`. Task 3 의 `demo` 프로파일이 이 이름으로 SSM 값을 주입한다. 이름을 바꾸면 Task 3·8 이 깨진다.

**배경:** 시드가 BCrypt 해시를 파일에 박아두고 있어(`v_hash`, 16행) 비밀번호가 전부 `password` 다. 이 시드를 그대로 공개 도메인에 올리면 **누구나 `platform@school.com` 으로 PLATFORM_ADMIN 로그인**이 가능하다. 시드 파일을 복제하지 않고(19KB 중복 방지) 해시만 주입 지점으로 바꾼다.

**⚠️ 체크섬 경고:** 적용이 끝난 마이그레이션 파일을 수정하므로 **기존 로컬 DB 는 Flyway checksum mismatch 로 기동에 실패한다.** 로컬 postgres 는 영속 볼륨이 없으므로 `docker compose down` 후 `up` 하면 해소된다. `stop`/`start` 로는 해소되지 않는다.

- [ ] **Step 1: 시드의 해시를 placeholder 로 교체**

`backend/src/main/resources/db/migration-local/V2__seed_data.sql` 16행:

```sql

--   local: application.yml 에 박힌 기본값(평문 "password")
--   demo : SSM Parameter Store 의 값(공개 도메인이라 "password" 를 쓰면 안 된다)
-- 이 위치(db/migration-local)는 local·demo 프로파일에서만 스캔에 추가되므로 prod 에는 적용되지 않는다.
```

- Produces: 필수 환경변수 `SEED_PASSWORD_HASH` — Task 8 이 SSM 에서 읽어 주입한다.

**배경 (세 결함을 한 번에 해소):**
- **B1** — prod 는 시드가 없어 계정이 0개인데, `AuthCommandService:46` 이 회원가입에서 `ACADEMY_ADMIN`·`PLATFORM_ADMIN` 을 403 으로 막고 `MemberController` 도 `PLATFORM_ADMIN` 생성을 거부한다. **최초 관리자를 만들 경로가 코드상 부재**하므로 시드 없이는 아무도 로그인할 수 없다.
- **B2** — prod 는 `location.mock.enabled=false`·`bus-gps.enabled=true`. 실 기사 단말이 없는 데모에서 그대로 쓰면 버스가 움직이지 않아 관제 화면이 정지 상태로 보인다.
- **B4** — `spring.profiles.active` 기본값이 `local` 이라, 프로파일을 명시하지 않으면 운영에서 localhost DB 를 찾는다.

- [ ] **Step 1: `demo` 프로파일 섹션 추가**

`application.yml` **맨 끝**(prod 섹션 뒤)에 추가한다.

```yaml
---
# 데모 배포 프로파일 — prod 를 기준으로 두 가지를 더한 것이다.
#
#  (1) 데모 시드 로드. prod 는 시드가 없어 계정이 0개인데, PLATFORM_ADMIN·ACADEMY_ADMIN 은
#      API 로 만들 수 없다(AuthCommandService 가 403, MemberController 도 거부).
#      즉 시드 없이 배포하면 **아무도 로그인할 수 없다.**
#  (2) Mock 위치 소스 활성. 실 기사 단말이 없으므로 prod 설정 그대로면 버스가 움직이지 않아
#      실시간 관제 화면이 정지 상태로 보인다. prod 와 정확히 반대로 둔다.
#
# prod 의 datasource·redis·kafka 블록을 상속하지 않고 다시 적는다. spring.profiles.group 으로
# 묶으면 줄은 줄지만 "지금 어떤 값이 쓰이는지"를 이 파일만 봐서 알 수 없게 된다 —
# 배포 설정은 영리함보다 한눈에 보이는 편이 낫다.
spring:
  config:
    activate:
      on-profile: demo
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST}
      port: ${REDIS_PORT:6379}
  kafka:
    bootstrap-servers: ${KAFKA_BOOTSTRAP_SERVERS}
  flyway:
```

```java
import static org.assertj.core.api.Assertions.assertThat;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

import org.junit.jupiter.api.BeforeAll;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

/**
 * 배포 설정이 위험한 기본값으로 되돌아가는 것을 막는 가드.
 *
 * <p>여기서 막는 사고는 전부 "조용히 성공하는" 종류다 — 앱은 정상 기동하지만
 * 공개 도메인에 약한 계정이나 개발용 설정이 열린 채로 뜬다. 테스트가 없으면

 *
 * <p>파일 텍스트만 읽으므로 Docker·DB 없이 실행된다.
 */
class DeploymentConfigGuardTest {

    private static String applicationYml;

    @BeforeAll
    static void readConfig() throws IOException {
        applicationYml = Files.readString(Path.of("src/main/resources/application.yml"));
    }

    @Test
    @DisplayName("demo 프로파일의 시드 비밀번호 해시에 기본값이 없다")
    void demoSeedHashHasNoDefault() {

        assertThat(applicationYml)
                .as("demo 프로파일은 SEED_PASSWORD_HASH 를 기본값 없이 요구해야 한다")

    @DisplayName("prod 프로파일은 Mock 위치 소스를 켜지 않는다")
    void prodKeepsMockDisabled() {
        String prodSection = sectionOf("on-profile: prod");
        // ⚠️ 단순히 "enabled: true 가 없다"로 검사하면 안 된다 — prod 에는 gps.enabled: true 가
        //    정상적으로 존재한다. 반드시 키와 값을 붙여서 본다.
        assertThat(prodSection)
                .as("prod 는 실 GPS 전용이다. Mock 을 켜면 실제 단말 좌표를 가짜가 덮어쓴다")
                .contains("    mock:\n      enabled: false")
                .contains("    bus-mock:\n      enabled: false");
    }

    @Test
    @DisplayName("demo 프로파일은 Mock 위치 소스를 켠다")
    void demoEnablesMock() {
        String demoSection = sectionOf("on-profile: demo");
        assertThat(demoSection)
                .as("실 기사 단말이 없는 데모에서 Mock 을 끄면 버스가 움직이지 않는다")
                .contains("    mock:\n      enabled: true")
                .contains("    bus-mock:\n      enabled: true");

    private String sectionOf(String marker) {

                return section;
            }
        }
        throw new AssertionError("프로파일 섹션을 찾지 못했다: " + marker);
    }
```

- [ ] **Step 1: 스크립트 작성**

```bash
#!/usr/bin/env bash
# Let's Encrypt 인증서 최초 발급 (EC2 에서 1회만 실행).
#
# 왜 standalone 인가:
#   nginx 는 인증서가 없으면 기동을 못 하고(ssl_certificate 파일 부재),
#   certbot 의 webroot 방식은 80 포트에서 응답하는 웹서버를 필요로 한다 — 순환이다.
#   최초 1회는 certbot 이 자체 웹서버를 띄워(standalone) 끊고, 이후 갱신은
#   docker-compose.prod.yml 의 certbot 컨테이너가 webroot 방식으로 처리한다.
#
# 사용법:
#   ./init-cert.sh api.내도메인.com 내메일@example.com
set -euo pipefail

DOMAIN="${1:?사용법: init-cert.sh <api 도메인> <이메일>}"
EMAIL="${2:?사용법: init-cert.sh <api 도메인> <이메일>}"

# compose 프로젝트명은 디렉터리명(/opt/school-bus → school-bus)에서 나온다.
# 그래서 볼륨 실제 이름은 school-bus_certbot-conf 다. 다른 경로에 배치했다면 여기를 맞춘다.
CONF_VOLUME="${CONF_VOLUME:-school-bus_certbot-conf}"
WWW_VOLUME="${WWW_VOLUME:-school-bus_certbot-www}"

docker volume create "$CONF_VOLUME" >/dev/null
docker volume create "$WWW_VOLUME"  >/dev/null

# 80 포트를 잠깐 비워야 한다 — 이미 proxy 가 떠 있으면 발급이 실패한다.
if docker ps --format '{{.Names}}' | grep -q 'proxy'; then
    echo "proxy 컨테이너가 80 포트를 쓰고 있다. 먼저 내린다."
    docker compose -f /opt/school-bus/docker-compose.prod.yml stop proxy || true
fi

docker run --rm -p 80:80 \
    -v "$CONF_VOLUME:/etc/letsencrypt" \
    -v "$WWW_VOLUME:/var/www/certbot" \
    certbot/certbot certonly --standalone \
    -d "$DOMAIN" \
    --email "$EMAIL" \
    --agree-tos --no-eff-email --non-interactive

echo
echo "발급 완료: /etc/letsencrypt/live/$DOMAIN/"
echo "다음 단계:"
echo "  1) infra/proxy/nginx.prod.conf 의 api.example.com 을 $DOMAIN 으로 바꾼다"
echo "  2) docker compose -f /opt/school-bus/docker-compose.prod.yml up -d"
```

**배경:** 시크릿을 저장소나 AMI 에 두지 않기 위해, 배포 때마다 SSM Parameter Store 에서 읽어 `.env` 를 새로 만든다. compose 는 `${VAR}` 를 해석할 파일이 필요하므로 메모리가 아니라 파일이어야 한다(권한 600).

- [ ] **Step 1: 스크립트 작성**

`infra/scripts/deploy.sh`

```bash
#!/usr/bin/env bash
# EC2 에서 실행되는 배포 스크립트. GitHub Actions 가 SSM Send Command 로 호출한다.
#
# 사용법:  deploy.sh <이미지태그>     예) deploy.sh 9f2c1ab
#
# 이 스크립트가 실행될 때 docker-compose.prod.yml 과 infra/ 는 워크플로가 S3 로 이미
# 동기화해 둔 상태다(저장소를 EC2 에 클론하지 않는다 — 비공개 저장소 자격증명을 두지 않기 위해).
set -euo pipefail

APP_DIR=/opt/school-bus
ENV_FILE="$APP_DIR/.env"
PARAM_PREFIX="/school-bus/demo"
AWS_REGION="${AWS_REGION:-ap-northeast-2}"
IMAGE_TAG="${1:?사용법: deploy.sh <이미지태그>}"
COMPOSE="docker compose -f $APP_DIR/docker-compose.prod.yml --env-file $ENV_FILE"

get_param() {
    # 조회 실패(비영 종료코드) 또는 빈 값/"None" 이면 어떤 파라미터인지 stderr 에
    # 찍고 실패로 리턴한다. 호출부가 반드시 단독 대입문(`X="$(get_param ...)"`)으로
    # 받아야 하는 이유는 아래 참고 — printf 같은 다른 명령의 인자 자리에서 바로
    # 명령 치환하면 그 명령 자체는 성공하므로 set -e 가 실패를 잡지 못한다.
    local name="$1" value
    if ! value="$(aws ssm get-parameter --region "$AWS_REGION" --name "$PARAM_PREFIX/$name" \
            --with-decryption --query 'Parameter.Value' --output text)"; then
        echo "오류: SSM 파라미터 조회 실패 — $PARAM_PREFIX/$name" >&2
        return 1
    fi
    if [[ -z "$value" || "$value" == "None" ]]; then
        echo "오류: SSM 파라미터 값이 비어 있음 — $PARAM_PREFIX/$name" >&2
        return 1
    fi
    printf '%s' "$value"
}

echo "== 1. SSM 에서 시크릿을 읽어 .env 생성 =="
# umask 077 로 만들어 다른 사용자가 읽지 못하게 한다.
# .env 를 파일로 남기는 이유 — compose 가 ${VAR} 를 해석할 때 파일이 필요하다(메모리로는 안 됨)
umask 077
: > "$ENV_FILE"
# 반드시 단독 대입문으로 먼저 받는다 — get_param 이 실패하면 대입문 자체가
# 비영 종료코드가 되어 set -e 가 그 자리에서 스크립트를 죽인다.
ECR_REGISTRY="$(get_param ECR_REGISTRY)"
DB_PASSWORD="$(get_param DB_PASSWORD)"
JWT_SECRET="$(get_param JWT_SECRET)"
SEED_PASSWORD_HASH="$(get_param SEED_PASSWORD_HASH)"
CORS_ALLOWED_ORIGINS="$(get_param CORS_ALLOWED_ORIGINS)"
WS_ALLOWED_ORIGIN_PATTERNS="$(get_param WS_ALLOWED_ORIGIN_PATTERNS)"
NAVER_DIRECTIONS_KEY_ID="$(get_param NAVER_DIRECTIONS_KEY_ID)"
NAVER_DIRECTIONS_KEY="$(get_param NAVER_DIRECTIONS_KEY)"
ROUTING_PROVIDER="$(get_param ROUTING_PROVIDER)"
{
    printf 'AWS_REGION=%s\n'                 "$AWS_REGION"
    printf 'IMAGE_TAG=%s\n'                  "$IMAGE_TAG"
    printf 'ECR_REGISTRY=%s\n'               "$ECR_REGISTRY"
    printf 'DB_PASSWORD=%s\n'                "$DB_PASSWORD"
    printf 'JWT_SECRET=%s\n'                 "$JWT_SECRET"
    printf 'SEED_PASSWORD_HASH=%s\n'         "$SEED_PASSWORD_HASH"
    printf 'CORS_ALLOWED_ORIGINS=%s\n'       "$CORS_ALLOWED_ORIGINS"
    printf 'WS_ALLOWED_ORIGIN_PATTERNS=%s\n' "$WS_ALLOWED_ORIGIN_PATTERNS"
    printf 'NAVER_DIRECTIONS_KEY_ID=%s\n'    "$NAVER_DIRECTIONS_KEY_ID"
    printf 'NAVER_DIRECTIONS_KEY=%s\n'       "$NAVER_DIRECTIONS_KEY"
    printf 'ROUTING_PROVIDER=%s\n'           "$ROUTING_PROVIDER"
} >> "$ENV_FILE"

echo "== 2. ECR 로그인 후 새 이미지 수신 =="
ECR_REGISTRY="$(get_param ECR_REGISTRY)"
aws ecr get-login-password --region "$AWS_REGION" \
    | docker login --username AWS --password-stdin "$ECR_REGISTRY"

$COMPOSE pull backend

echo "== 3. 기동 =="
# 단일 인스턴스라 재생성 중 수십 초 다운타임이 생긴다(설계 문서 §4.3). 데모에서는 수용한다.
$COMPOSE up -d

echo "== 4. 스모크 테스트 (최대 3분 대기) =="
for _ in $(seq 1 36); do
    if $COMPOSE exec -T backend \
         curl -fsS http://localhost:8080/actuator/health 2>/dev/null | grep -q '"status":"UP"'; then
        echo "배포 성공 (tag=$IMAGE_TAG)"
        docker image prune -f >/dev/null
        exit 0
    fi
    sleep 5
done

echo "배포 실패 — 3분 안에 헬스체크가 UP 이 되지 않았다" >&2
$COMPOSE logs --tail 120 backend >&2
exit 1
```

```bash
#!/usr/bin/env bash
# Postgres 덤프를 S3 로 올린다. /etc/cron.d/schoolbus-backup 이 매일 03:10 에 호출한다.
#
# 보관 기간은 스크립트가 아니라 S3 수명주기 규칙(7일)으로 관리한다 —
# 삭제 로직을 스크립트에 두면 버그 하나로 백업 전체가 지워질 수 있다.
set -euo pipefail

APP_DIR=/opt/school-bus
BUCKET="${BACKUP_BUCKET:?BACKUP_BUCKET 미설정}"
AWS_REGION="${AWS_REGION:-ap-northeast-2}"
STAMP="$(date +%F-%H%M)"
DUMP="/tmp/schoolbus-$STAMP.sql.gz"

trap 'rm -f "$DUMP"' EXIT

docker compose -f "$APP_DIR/docker-compose.prod.yml" --env-file "$APP_DIR/.env" \
    exec -T postgres pg_dump -U schoolbus schoolbus | gzip > "$DUMP"

# 빈 덤프를 올리면 "백업이 있다"는 착각만 남는다. 파이프 중간 실패는 종료코드로 안 잡히므로
# 크기로 한 번 더 확인한다(정상 덤프는 최소 수십 KB).
SIZE=$(stat -c%s "$DUMP")
if [ "$SIZE" -lt 10240 ]; then
    echo "덤프가 10KB 미만($SIZE B) — 백업 실패로 간주한다" >&2
    exit 1
fi

aws s3 cp --region "$AWS_REGION" "$DUMP" "s3://$BUCKET/db/$STAMP.sql.gz"
echo "백업 완료: s3://$BUCKET/db/$STAMP.sql.gz ($SIZE B)"
```

**Interfaces:**

**배경:** 테스트가 `@SpringBootTest` 라 Postgres·Redis·Kafka 가 필요하다. 러너에서 **루트 `docker-compose.yml` 로 인프라만 띄우면** 백엔드 기본 설정(localhost:5432·6379·29092)이 그대로 맞는다.

- [ ] **Step 1: 워크플로 작성**

`.github/workflows/deploy-backend.yml`

```yaml
# 백엔드 배포: 테스트 → 이미지 빌드 → ECR → SSM 으로 EC2 배포.
#
# EC2 에서 빌드하지 않는 이유: Gradle(Java 25) 빌드가 2GB 안팎을 먹어, 실행 중인
# Kafka·Spring·Postgres 와 경합하면 OOM 이 난다. 빌드는 러너에서 끝낸다.
name: deploy-backend

on:
  push:
    branches: [main]
    paths:
      - 'backend/**'
      - 'docker-compose.prod.yml'
      - 'infra/**'
      - '.github/workflows/deploy-backend.yml'
  workflow_dispatch:

# 배포가 겹치면 옛 이미지가 새 이미지를 덮어쓸 수 있다. 취소하지 않고 줄을 세운다.
concurrency:
  group: deploy-backend
  cancel-in-progress: false

permissions:
  id-token: write   # OIDC 로 AWS 역할을 assume 하는 데 필요(장기 액세스키를 두지 않는다)
  contents: read

env:
  AWS_REGION: ap-northeast-2
  ECR_REPOSITORY: school-bus-backend

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '25'
          cache: gradle

      # @SpringBootTest 가 실제 DB·Redis·Kafka 를 요구한다. 루트 compose 가 노출하는
      # 포트(5432·6379·29092)가 application.yml local 기본값과 그대로 맞는다.
      - name: 테스트용 인프라 기동
        run: docker compose up -d postgres redis kafka

      - name: 테스트
        working-directory: backend
        run: ./gradlew test

      - name: AWS 자격 획득 (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_DEPLOY_ROLE_ARN }}
          aws-region: ${{ env.AWS_REGION }}

      - name: ECR 로그인
        id: ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: 이미지 빌드·푸시
        working-directory: backend
        env:
          REGISTRY: ${{ steps.ecr.outputs.registry }}
          TAG: ${{ github.sha }}
        run: |
          docker build -t "$REGISTRY/$ECR_REPOSITORY:$TAG" \
                       -t "$REGISTRY/$ECR_REPOSITORY:latest" .
          docker push "$REGISTRY/$ECR_REPOSITORY:$TAG"
          docker push "$REGISTRY/$ECR_REPOSITORY:latest"

      # compose·nginx·스크립트 변경분을 EC2 에 전달하는 통로.
      # 저장소를 EC2 에 클론하지 않는다 — 비공개 저장소 자격증명을 서버에 두지 않기 위해서다.
      #
      # infra/proxy/.htpasswd(Swagger Basic Auth 계정 파일)는 운영자가 EC2 에 직접
      # 생성하는 시크릿이라 저장소·CI 어디에도 두지 않는다(.gitignore:26). --delete 는
      # 필터로 제외된 파일을 삭제 대상에서도 제외하므로(`aws s3 sync help` 의 --delete
      # 설명) --exclude 로 지키지 않으면 이 파일이 배포마다 S3·EC2 양쪽에서 삭제된다.
      - name: 배포 파일 S3 동기화
        env:
          BUCKET: ${{ secrets.DEPLOY_BUCKET }}
        run: |
          aws s3 sync infra "s3://$BUCKET/infra" --delete --exclude "proxy/.htpasswd"
          aws s3 cp docker-compose.prod.yml "s3://$BUCKET/docker-compose.prod.yml"

      - name: EC2 배포 (SSM Send Command)
        env:
          INSTANCE_ID: ${{ secrets.EC2_INSTANCE_ID }}
          BUCKET: ${{ secrets.DEPLOY_BUCKET }}
          TAG: ${{ github.sha }}
        run: |
          CMD_ID=$(aws ssm send-command \
            --instance-ids "$INSTANCE_ID" \
            --document-name AWS-RunShellScript \
            --comment "deploy $TAG" \
            --parameters commands="[
              'set -e',
              'aws s3 sync s3://$BUCKET/infra /opt/school-bus/infra --delete --exclude proxy/.htpasswd',
              'aws s3 cp s3://$BUCKET/docker-compose.prod.yml /opt/school-bus/docker-compose.prod.yml',
              'chmod +x /opt/school-bus/infra/scripts/*.sh /opt/school-bus/infra/certbot/*.sh',
              '/opt/school-bus/infra/scripts/deploy.sh $TAG'
            ]" \
            --query 'Command.CommandId' --output text)

          echo "CommandId=$CMD_ID"

          # aws ssm wait command-executed 는 delay 5초 × maxAttempts 20 = 100초 고정 상한이고
          # --delay/--max-attempts 오버라이드를 제공하지 않는다(botocore ssm waiters-2.json,
          # `aws ssm wait command-executed help`). deploy.sh 는 SSM get-parameter 9회 + ECR
          # pull + 최대 3분 헬스체크로 100초를 넘기는 게 정상 경로이므로, waiter 를 쓰면 배포가
          # 진행 중인데도 거짓 실패로 보고된다. get-command-invocation 을 직접 폴링해
          # 종료 상태(Success/Cancelled/TimedOut/Failed/Cancelling)로만 판정한다.
          MAX_WAIT_SECONDS=600
          POLL_INTERVAL_SECONDS=10
          ELAPSED=0
          STATUS="Unknown"

          while [ "$ELAPSED" -lt "$MAX_WAIT_SECONDS" ]; do
            # get-command-invocation 은 명령이 아직 인스턴스에 도달하기 전이면
            # InvocationDoesNotExist 로 에러를 반환할 수 있다(SSM waiter 도 이 에러를 retry
            # 대상으로 취급한다) — 이 구간을 실패로 오판하지 않도록 STATUS 를 그대로 두고
            # 다음 폴링으로 넘어간다. 실패한 호출의 결과로 STATUS 를 덮어쓰지 않는다.
            if POLLED_STATUS="$(aws ssm get-command-invocation --command-id "$CMD_ID" \
                  --instance-id "$INSTANCE_ID" --query Status --output text 2>&1)"; then
              STATUS="$POLLED_STATUS"
              case "$STATUS" in
                Success | Cancelled | TimedOut | Failed | Cancelling) break ;;
              esac
            elif [[ "$POLLED_STATUS" != *InvocationDoesNotExist* ]]; then
              echo "::warning::get-command-invocation 조회 실패, 재시도: $POLLED_STATUS"
            fi
            sleep "$POLL_INTERVAL_SECONDS"
            ELAPSED=$((ELAPSED + POLL_INTERVAL_SECONDS))
          done

          echo "최종 상태: $STATUS (경과 ${ELAPSED}s)"
          aws ssm get-command-invocation --command-id "$CMD_ID" --instance-id "$INSTANCE_ID" \
            --query StandardOutputContent --output text || true

          if [ "$STATUS" = "Success" ]; then
            echo "배포 성공"
            exit 0
          fi

          if [ "$ELAPSED" -ge "$MAX_WAIT_SECONDS" ]; then
            echo "::error::배포 상태 판정 상한(${MAX_WAIT_SECONDS}s) 초과 — 배포가 아직 진행 중일 수 있음 (status=$STATUS)"
          else
            echo "::error::배포 실패 (status=$STATUS)"
          fi
          aws ssm get-command-invocation --command-id "$CMD_ID" --instance-id "$INSTANCE_ID" \
            --query StandardErrorContent --output text || true
          exit 1
```

```yaml
# Flutter Web 배포: 빌드 → Vercel prebuilt 업로드.
#
# Vercel 에는 Flutter 빌더가 없다(Git 연동만으로는 빌드 불가). 그래서 여기서 빌드하고
# 완성된 산출물을 .vercel/output 규격으로 감싸 올린다.
name: deploy-web

  push:
    branches: [main]
    paths:
      - 'frontend/**'
      - '.github/workflows/deploy-web.yml'
  workflow_dispatch:

concurrency:
  group: deploy-web
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: frontend
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          channel: stable

      - run: flutter pub get
      - run: flutter analyze
      - run: flutter test

          VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
```
