## Global Constraints

모든 태스크의 요구사항에 아래가 암묵적으로 포함된다.

- **작업 디렉터리는 `backend/`** — 모든 Gradle 명령을 여기서 실행한다. 루트에서 실행하지 않는다.
- **기본 패키지는 `src.backend`** — 새 클래스는 반드시 이 하위에 둔다. 벗어나면 컴포넌트 스캔에서 빠진다.
- **Java 25 / Spring Boot 4.1.0** — 웹 스타터는 `spring-boot-starter-webmvc`(구 `-web` 아님).
- **테스트 규약**: AssertJ(`assertThat`·`assertThatThrownBy`)만 쓴다. `@ExtendWith(MockitoExtension.class)` 를 쓰지 않고 **필드에서 `mock(X.class)` 로 만들고 `new Service(...)` 로 직접 조립**한다. 메서드명은 `대상_조건_기대결과` 또는 한글 서술형(기존 파일의 방식을 따른다).
- **테스트 위치**: `backend/src/test/java/src/backend/<모듈>/<레이어>/<클래스명>Test.java` — main 패키지를 그대로 미러링한다.
- **DB 없이 돌린 기준선**: `BackendApplicationTests > contextLoads()` **1건 실패가 정상**이다(실제 PostgreSQL 필요). **2건 이상 실패해야 진짜 결함**이다. 이 1건을 "내가 깨뜨렸다"고 보고하지 않는다.
- **`./gradlew clean` 금지** — 여러 작업이 동시에 돌 수 있다. 다시 돌려야 하면 `--rerun-tasks` 를 쓴다.
- **`git add -A` / `git add .` 금지** — 반드시 각 태스크의 **Files 에 적힌 경로만** 지정해 add 한다. 다른 사람의 미완성 작업이 딸려 들어간다.
- **스키마 변경은 기존 마이그레이션 수정이 아니라 새 버전 파일 추가**로만 한다. `V1__init_schema.sql` 은 절대 고치지 않는다.
- **문서는 이 태스크들에서 건드리지 않는다.** 문서 반영은 전부 끝난 뒤 별도로 한다.

- [ ] **Step 3: 서비스에 범위 검증을 넣는다**

`RouteQueryService.getStops` 를 아래로 바꾼다.

```java
    /**
     * 정류장 목록 — 학원 구성원이면 역할과 무관하게 볼 수 있다(기사·학부모·학생 포함).
     * 다만 <b>다른 학원의 노선은 볼 수 없다</b> — 정류장 좌표는 그 학원의 운행 구역을 드러낸다.
     */
    @Transactional(readOnly = true)
    public List<StopResponse> getStops(AuthUser user, Long routeId) {
        Route route = routeRepository.findById(routeId)
                .orElseThrow(() -> new BusinessException(ErrorCode.NOT_FOUND, "노선을 찾을 수 없습니다"));
        Long ownerTenantId = route.getTenant().getId();
        if (!user.isPlatformAdmin() && !user.belongsToTenant(ownerTenantId)) {
            throw new BusinessException(ErrorCode.FORBIDDEN);
        }
        return stopRepository.findByRouteIdOrderBySeqAsc(routeId).stream()
                .map(StopResponse::from)
                .toList();
    }
```

`BusinessException` · `ErrorCode` import 를 추가한다(`src.backend.global.error.*`).

```java
     * 인가 애너테이션이 하나도 없는 매핑을 찾는다. 클래스 레벨 애너테이션이 있으면 그 컨트롤러는 통과다.

     */
    private static final List<String> INTENTIONALLY_OPEN = List.of();

    @Test
    void 인가_애너테이션이_없는_컨트롤러가_없다() {
        List<String> unguarded = new ArrayList<>();
        for (Path file : controllerSources()) {
            String source = String.join("\n", readLines(file));
            String name = file.getFileName().toString();
            if (name.equals("AuthController.java") || INTENTIONALLY_OPEN.contains(name)) {
                continue;   // 로그인·회원가입은 permitAll 경로다
            }
            if (!source.contains("@Can")) {
                unguarded.add(name);
            }
        }
        assertThat(unguarded)
                .as("컨트롤러에 인가 애너테이션이 하나도 없다 — global/security/authz 의 애너테이션을 붙인다")
                .isEmpty();
    }
```

**배경:** `enableUnsafeDefaultTyping()` 은 저장 값에 `@class` 를 심고 **읽을 때 그 문자열이 가리키는 아무 타입이나 만든다.** 운영에서 Redis 는 호스트 포트를 열지 않아 실제 노출은 제한적이지만, 이 저장소가 Redis 에 넣는 타입은 좌표 DTO 2종(`LocationPing`·`BusLocationPing`)뿐이다. 허용 타입을 그 범위로 좁히면 이 위험 부류 자체가 사라진다. 메서드 이름이 스스로 `Unsafe` 라고 말하고 있다.

- [ ] **Step 1: 라이브러리 API 를 문서로 확인한다 — 추측하지 않는다**

`GenericJacksonJsonRedisSerializer`(Jackson 3 기반)는 Spring Data Redis 의 **신형 클래스**라 빌더 API 가 구버전 `GenericJackson2JsonRedisSerializer` 와 다르다. **기억으로 메서드 이름을 쓰지 말고** context7 로 확인한다.

- `resolve-library-id` 로 Spring Data Redis 를 찾고 `query-docs` 로 `GenericJacksonJsonRedisSerializer` 의 builder 옵션(허용 타입 제한 / `PolymorphicTypeValidator` 대응물)을 조회한다.
- 확인이 안 되면 **추측해서 컴파일만 통과시키지 않는다.** "API 미확인 — 변경 보류" 로 보고하고 이 태스크를 종료한다. 잘못 좁히면 좌표 조회가 런타임에 조용히 실패한다.
