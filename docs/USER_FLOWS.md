## 1. 역할별 진입 지도

| 역할 | 제품 | 첫 화면 (`ACTIVE`) | 접근 가능 범위 | 승인 주체 |
|---|---|---|---|---|
| 학부모 | 학부모·학생 앱 | 홈 — 자녀별 오늘 상태 카드 | 자녀 스케줄 · 실시간 위치(ETA 부재) · 탑승 토글 · 변경 신청 · 알림 | 학원 관계자 |
| 학생 | 학부모·학생 앱 | 홈 — 본인 오늘 상태 | 본인 스케줄 · 실시간 위치 · 노선 · 알림 · 인증 코드 생성 (조회 전용) | 학원 관계자 |
| 버스기사 | 매니저 앱 | 담당 노선 — 운행 카드 | 확정 노선 · 승하차지 리스트 · 명단(조회) · 운행모드 · 도착 처리 · 비상 알림 | 학원 관계자 |
| 동승자 | 매니저 앱 | 담당 노선 — 승하차지 리스트 | 명단 · **승하차 상태 변경(유일 주체)** · 지연 알림 · 예외 보고. **지도 화면 부재** | 학원 관계자 |
| 학원 관계자 | 관계자 웹 | 운행 대시보드 | 소속 학원 전 데이터 · 가입 승인 · ②구간 승인 · 노선·명단·인력·차량 관리 | **메인 관리자** |
| 메인 관리자 | 운영사 콘솔 | 학원 관리 | 전 학원 관제(ETA 포함) · 학원 CRUD · 관계자 가입 승인 · 차단 해제 | 내부 발급 (가입 경로 부재) |

**진입 차단 계층** — 로그인 성공 여부(인증)와 데이터 접근 권한(인가)은 별개의 검사. 계정 상태가 `PENDING` · `REJECTED` 면 역할과 무관하게 승인 대기 화면 하나로 수렴하고, 나머지 API 는 서버 인가 계층에서 403 (C-01 · FEATURE_SPEC §3.6).

## 2. 공통 — 가입 · 승인 · 로그인 · 차단

### UF-X-01. form 회원가입 · 학원 선택

`[회원가입 폼 입력 — 아이디·비밀번호·이름·연락처]` → `[역할 선택 — 학부모/학생/기사/동승자/관계자]` → `[학원 검색 — 학원명 또는 학원 코드]` → 결과 `{학원명} · {지역} · {학원 코드}` 확인 → `[선택]` → `POST /auth/signup` → `SignupRequest` 생성 · 계정 `PENDING` → 승인 대기 화면

**분기 · 예외**

- (아이디 중복) → ✕ 인라인 유효성 에러 — 다음 단계 진행 불가
- (학원 미선택) → ✕ 제출 버튼 비활성
- (검색 결과 부재) → "학원을 찾을 수 없습니다 — 학원에 문의해 주세요". 사용자가 학원을 생성하는 경로 부재
- (비활성 학원) → 검색 결과에서 제외 — 신규 가입 차단 (O-01)
- (역할 = 관계자) → 승인 대기열이 **메인 관리자** 콘솔로 전달 (C-01 · O-02)
- (역할 = 관계자 · 해당 학원에 관계자 1명 존재) → 메인 관리자 승인 단계에서 ✕ 초과 승인 차단 (학원당 1명)
- (메인 관리자) → 가입 경로 자체가 부재 — 내부 발급

### UF-X-02. 승인 대기 · 거절 · 재신청

`PENDING` → 승인 대기 화면(`GET /auth/signup-status`) — 신청 학원 · 신청 일시 · 현재 상태 · 학원 문의처 · `로그아웃` → 관계자(또는 메인 관리자) 수락 + 레코드 연결 → `ACTIVE` → 역할별 홈

**분기 · 예외**

- (`PENDING` 상태로 타 화면 접근) → ✕ 서버 인가 계층 403 — 홈 · 명단 · 노선 · 실시간 위치 · 알림 목록 · 설정 전부 차단
- (`PENDING` 수신 알림) → 승인·거절 결과만. 운행 알림은 대상 밖
- (거절 `REJECTED`) → 같은 화면에 거절 사유 표시 + `[학원 재선택 · 재신청]` 진입점 → `POST /auth/signup/reapply`
- (수락 시 레코드 연결 누락) → ✕ 서버가 승인 처리를 거부 — 연결 부재 계정은 로그인은 되나 데이터 조회 불가 (AUTH-11)

### UF-X-03. 로그인 · 자동 로그인

`[아이디·비밀번호 입력]` → `POST /auth/login` → access(단기) + refresh(장기) 발급 → 계정 상태 판정 → `ACTIVE` 면 역할별 홈

**분기 · 예외**

- (앱 재실행) → 기기 보안 저장소의 refresh 로 access 자동 재발급 — 자동 로그인 기본 (C-14)
- (웹 새로고침 · 탭 재개) → 브라우저가 보관한 HttpOnly 쿠키로 access 자동 재발급. 웹은 access 를 메모리에만 두므로 **새로고침마다 이 경로를 거치는 것이 정상** (C-14 · API_SPEC §1.2.1)
- (refresh 만료 · 로그아웃 · 계정 차단) → 토큰 무효화 → 로그인 화면으로 이동 후 재로그인 요구
- (`PENDING` · `REJECTED`) → 로그인은 성공하되 승인 대기 화면으로 고정 (UF-X-02)
- (`BLOCKED`) → ✕ 로그인 실패 — 해제는 메인 관리자만 (UF-O-03)

### UF-X-04. 로그인 실패 누적 · 계정 차단

`[비밀번호 오입력]` → 실패 횟수 누적 → **5회** 도달 → 계정 상태 `BLOCKED` → ✕ 이후 모든 로그인 실패

**분기 · 예외**

- (차단 단위) → **계정 단위**. IP 차단 부재 — 학원 와이파이·가정 공용 회선의 무관한 사용자까지 잠기는 것을 방지 (C-11)
- (사용자 자력 해제) → 경로 부재. 메인 관리자만 해제 (UF-O-03)
- (아이디·비밀번호 분실) → `[전화번호 인증]` 또는 `[관리자 경유 복구]` (AUTH-08)

## 3. 학부모 플로우

### UF-P-01. 자녀 연결 — 인증 코드 (P-02 · S-05)

홈 → `[설정 · 자녀 연결 요청]` → `POST /me/students/link-requests` → 학생 앱에 연결 요청 푸시 도착 → 학생이 `[인증 코드 생성]`(`POST /me/link-code`) → `[학부모가 코드 입력]` → `POST /me/students/link` → 서버 인증 → `GuardianStudent` 생성 → 홈에 자녀 반영

**분기 · 예외**

- (다자녀) → 자녀 1명당 같은 프로세스 반복 — 학부모 재가입 부재
- (코드 만료 · 불일치) → ✕ 연결 실패 → `[재요청]`
- (학생 계정 미보유) → ✕ 연결 불가 — 서비스 대상은 휴대전화(학생 계정) 보유 학생 (C-13)
- (동생 신규 등록) → 관계자가 기존 학부모 계정에 연결만 추가 (AUTH-11)
- (퇴원) → 연결 해제, 과거 이력은 보존

### UF-P-02. 다자녀 화면 전환

홈 → (자녀 2명 이상) 자녀 선택 UI 노출 → `[자녀 선택]` → 실시간 위치 · 상세 노선 · 탑승 토글 · 변경 신청이 선택 자녀 기준으로 전환

**분기 · 예외**

- (자녀 1명) → 선택 UI 비노출
- (알림) → **자녀 선택과 무관하게 전 자녀 알림 수신**. 모든 문구에 자녀 이름 포함 (ATT-03)
- (자녀별 독립성) → 자녀마다 호차·노선·승하차지·탑승 여부가 각각 다름 — 형제의 동일 호차 보장 부재

### UF-P-03. 요일별 등하원 주소 설정 (P-05)

홈 → `[설정 · 요일별 주소]` → 요일(월~일) × 등원/하원별 주소 직접 기입 → `PATCH /students/{id}/weekly-address` → 서버 정상 처리 확인 → "처리되었습니다" 표시 → 저장 완료

**분기 · 예외**

- (기본 주소) → 개념 부재. 노선 산출은 요일별 주소가 유일 기준 (C-12)
- (미변경 요일) → 매주 같은 요일의 주소가 반복 적용
- (같은 날 일일 변경 존재) → **일일 변경 > 요일별 주소** — 해당 일만 일일 변경 적용, 이후 요일별 주소로 복귀 (P-06)
- (서버 처리 실패) → "처리되지 않았습니다" 명시 · 기존 값 유지 (C-10)

### UF-P-04. 회차별 탑승 토글 — ①구간 (P-03 · ATT-01)

홈 → (자녀 2명 이상) 자녀 선택 → `[등원/하원 스위치 OFF]` → `PATCH /students/{id}/runs/{runId}/intent` → 서버 확인 → 즉시 반영 · `RunRider.status` = `absent` → 매니저 앱 명단에서 개인 행 제외(집계는 "미등원 N명" 유지) → 노선 재최적화 → 관계자 통지

**분기 · 예외**

- (기본값) → 등원·하원 스위치 모두 ON
- (학부모 알림) → **발송 부재** — 학부모가 스스로 설정한 값 (C-02)
- (승하차지 잔여 탑승자 0명) → 재최적화로 **노선에서 제거** — ①구간에는 `skipped` 가 성립하지 않음. `skipped` 발생 경로는 **③구간 미등원**과 **운행 중 미승차** 둘뿐 (C-05)
- (OFF → ON 되돌리기 · ①구간) → 가능 — 재최적화 대상
- (②구간 진입) → UF-P-05 로 분기
- (③구간 = `Run.status` = `moving` 이후 · OFF) → **승인 없이 즉시 수용** — `absent` 기록. **노선 변경 부재**, 해당 승하차지는 **경로상 경유하되 정차하지 않음**(`skipped`) + 기사·동승자 즉시 푸시 (C-04 ③ · C-05)
- (③구간 · OFF → ON 되돌리기 · 위치 변경) → ✕ 불가 — 이미 배포된 노선에 승하차지를 되살릴 경로가 부재
- (서버 처리 실패) → 기존 상태 복구 · "처리되지 않았습니다" (C-10)
- (학생 계정) → 이 기능 비노출 — 학부모 전용

### UF-P-05. 회차별 탑승 토글 — ②구간 승인 경유 (C-04)

출발 **30분 전** 도달 → 토글 화면에 남은 시간 카운트다운 노출 → `[스위치 OFF]` → 승인 대기로 접수(즉시 반영 부재) → 관계자에 푸시 (REQ-05) → 학부모 화면 상태 `pending` → 관계자가 **전/후 노선 대조 확인 후 승인** → `absent` 처리 + **노선 재최적화·재배포** → 기사·동승자 푸시 + 학부모 통보

**분기 · 예외**

- (승인 효과) → **재최적화 후 재배포** — 빠진 승하차지가 노선에서 제거되고 순서·소요시간이 갱신. 관리자가 승인 화면에서 전/후 대조를 보고 선택 (A-05)
- (거절 효과) → **기존 경로 유지** — 재최적화 부재
- (한도) → **회차당 1회** — 단위는 회차(`Run`). 등원 회차와 하원 회차가 각각 1회씩이며 서로 한도를 공유하지 않음. 소진 후 재신청은 ✕ "금일은 변경할 수 없습니다" 안내
- (거절) → 사유와 함께 학부모 통지 · 현상 유지
- (출발 시각 도달 또는 운행 시작 · 관계자 미응답) → ✕ **자동 거절** — 둘 중 먼저 오는 시점에 마감, **기존 노선 그대로 유지** + 학부모 통지 · **횟수 미소진** (X-02)
- (서버 처리 실패) → 기존 상태 복구 · **횟수 미소진** — 재신청 가능 (C-10)
- (②구간 추가) → ✕ 불가. ②구간에 수용되는 요청은 **미등원(제외)** 뿐이며 관계자의 강제 추가도 예외 부재 (A-06)

### UF-P-06. 일일 스케줄 변경 · 탑승 위치 변경 신청 (P-06 · REQ-01·02)

홈 → `[탑승일정/위치 변경]` → `[날짜 선택]` → `[변경 승하차 주소 입력]` → `[사유 입력(선택)]` → `[확인]` → `POST /students/{id}/change-requests` → **신청 완료**(변경 완료 아님) → **홈에 처리 대기 배지(N건)** + 신청 목록에 상태 뱃지 → `pending`(처리중) → `approved`(반영 완료) 또는 `rejected`(사유 표시)

**분기 · 예외**

- (①구간 · 출발 30분 전까지) → 승인 없이 즉시 반영 + 노선 재최적화 → 상태 바로 `approved`
- (②구간 · 30분 안쪽~출발 전) → 관리자 승인을 통해서만 반영. 승인 시 **재최적화·재배포**, 거절 시 기존 경로 유지 — 같은 회차의 탑승 토글과 **한도를 공유**(회차당 1회, UF-P-05)
- (③구간 · 운행 시작 후) → ✕ 위치 변경 불가 — "운행이 시작되어 변경할 수 없습니다". **탑승 취소(미등원)만** 별도 경로로 접수 (UF-P-04)
- (입력 주소가 기존 노선 범위 밖) → 접수는 성립하되 "학원 확인 후 반영" 안내 → 관계자가 강제 방문지로 처리 (UF-M-03)
- (대기 중 안내) → `pending` 동안에는 기존 승하차지 탑승 안내 유지 + **처리중 뱃지 상시 노출** — 신청 사실이 화면에서 사라지지 않음
- (종료 상태 오인) → 이 플로우의 종료는 **신청 완료**. 반영 여부는 상태 표시로만 확인

### UF-P-07. 실시간 버스 위치 · 노선 자세히 보기 (P-07 · P-08)

홈 · 실시간 운행 정보 → `[지도 진입]` → `GET /students/{id}/bus-position` + WS 구독 → 버스 현재 위치 + 노선 표시 → `[노선 자세히 보기]` → 승차지 이전 2개 · 승차지 · 하차지 요약 + 동승자 연락 버튼

**분기 · 예외**

- (ETA · 탑승 인원) → **비노출** — 노선에서 위치만 (C-08). 메인 관리자 관제 ETA 는 별개 (O-05)
- (확정 전) → 고정 노선 기준 표시 + "확정 전" 배지
- (변경분) → `added` 초록 · `removed` 빨강 · `skipped` 빨강 취소선 (C-09)
- (위치 신호 유실) → "마지막 확인 위치 · N분 전" 표기
- (운행 시간 아님) → 지도 대신 "운행 예정 시간" 안내
- (당일 `absent`) → 진입은 허용, "오늘은 버스를 이용하지 않습니다" 안내
- (기사 직접 연락) → 버튼 부재 — 스코프 제외

### UF-P-08. 알림 목록 · 알림 설정 (P-09)

홈 → `[알림]` → `GET /notifications` — 최근 **14일** 보관, 미읽음 배지 → `[알림 항목 선택]` → 읽음 처리 → 관련 화면 이동 / 설정 → `[알림 설정]` → `PATCH /me/notification-settings` — 도착 · 등하원 · 미승차 on/off

**분기 · 예외**

- (지연 알림) → 설정 항목 자체가 부재 — 항상 발송
- (off 동작) → **푸시만 차단**. 레코드는 항상 생성되어 목록·관계자 알림 로그에 존치
- (다자녀) → 자녀 선택과 무관하게 전 자녀 알림 수신, 문구에 자녀 이름 포함

## 5. 버스기사 플로우 — 운행 하루

### UF-D-01. 담당 회차 확인 (M-02 · M-07)

로그인(자동 로그인 기본) → 호차 자동 배정 확인 → `GET /manager/runs?date=today` → 운행 카드 — 호차 · 출발 시간 · 출발지 · 도착지 · 예상 소요시간

**분기 · 예외**

- (확정 전 · `Run.status` = `idle`) → 고정 노선 + "확정 전" 배지, "출발 30분 전 확정" 안내 → ✕ 회차 진입 불가
- (확정 후 · `confirmed`) → 변경 배지 노출 — `added` N / `removed` N
- (배정 회차 부재) → 빈 상태 화면 + "학원에 문의" 안내
- (호차 선택) → 단계 부재 — 계정 배정값으로 자동 결정
- (`PENDING` 계정) → 승인 대기 화면 하나만 (UF-X-02)

### UF-D-02. 승하차지 리스트 · 명단 조회 · 변경 확인 응답 (M-03 · M-04)

운행 카드 `[클릭]` → `GET /runs/{runId}/roster` → 승하차지 리스트(운행 순서 정렬) → `[승하차지 클릭]` → 명단 — 이름 · 사진 · 반 · 연락처(마스킹) · 특이사항 · 혼자 귀가 가능 여부 · 상태 → 확정 후 변경 발생 시 푸시 수신 → `[변경 목록 확인]` → `POST /runs/{runId}/ack-changes`

**분기 · 예외**

- (`absent` 학생) → 개인 행 제외. 집계에 "미등원 N명"만 유지 (RST-04)
- (`added` 승하차지·탑승자) → 초록 하이라이트
- (`skipped` 승하차지) → 빨강 취소선 + "이 승하차지는 오늘 탑승자가 없어 정차 부재" 안내. 목록에서 제거 부재, 순번 재부여 부재
- (상태 변경 버튼) → 기사 화면에 비노출 — 조회 전용 (C-06)
- (확인 응답 미수행) → 관계자 대시보드에 미확인으로 표시 (MON-05)

### UF-D-03. 운행모드 시작 (M-08 · M-10 · RUN-02)

`[운행 시작]`(출발 시각 **±3분** 에만 활성) → `POST /runs/{runId}/start` → `Run.status` = `moving` → ✕ 노선 전면 잠금 → 위치 송신 시작(**5~10초** 주기, `POST /runs/{runId}/position`) → 운행모드 화면(항상 다크) — 현재/다음 승하차지 대형 텍스트

**분기 · 예외**

- (출발 시각 ±3분 밖) → ✕ 버튼 비활성 — 오조작 방지. 3분 초과 지연 시 시작 수단 부재가 현재 상태 (X-01 미해결)
- (하원 회차) → 시작과 동시에 전원 자동 `boarded` (C-07)
- (등원 회차) → 승하차지별 승차 처리를 동승자가 수행 (UF-E-02)
- (운행모드 버튼 성격) → 전부 보고용(도착·지연·종료). 노선을 바꾸는 버튼 부재
- (알림) → 학부모·학생·관계자에 운행 시작 알림 (RUN-05)

### UF-D-04. 승하차지 도착 처리 (M-11 · RUN-04)

승하차지 진입 직전 → `[도착 처리]` → `POST /runs/{runId}/stops/{stopId}/arrive` → 도착 타임스탬프 서버 기록 → 현재/다음 승하차지 포인터 전진 → (최종 지점이면) **운행 종료 겸함** (C-15)

**분기 · 예외**

- ("곧 도착합니다" 예고 알림) → 이 조작이 트리거가 **아님**. 서버가 실시간 버스 위치 기반 이벤트로 자동 발송 (NTF-04). 도착 처리는 기록·포인터 전진 전용
- (동승자 명단) → 포인터가 전진해도 해당 승하차지 처리 명단은 **별개로 계속 열림** — 두 값을 묶으면 미처리 학생의 명단이 동승자 화면에서 사라짐
- (중복 처리) → ✕ 동일 승하차지 재처리 차단
- (다음이 `skipped`) → 미경유 안내 라인 + 그 다음 실제 경유지를 표시. 경로 안내·ETA 재계산 부재 — 최단거리 주행은 기사 판단 (C-05)
- (최종 지점 · 등원) → 학원 도착 처리 즉시 `Run.status` = `finished` + 전원 자동 `alighted` + 위치 송신 중단 (C-07 · C-15)
- (최종 지점 · 하원 · 전원 하차 완료) → 도착 처리 즉시 `finished`
- (최종 지점 · 하원 · 미하차 학생 존재) → 도착은 기록되고 **종료 보류** — `moving` 유지 + 미하차 목록 표시. 동승자가 마지막 학생을 `alighted` 처리하는 순간 서버가 자동으로 `finished` 전이 (RUN-06)
- (별도 종료 버튼) → 부재. 기사가 따로 누를 것이 없음 (C-15)
- (통신 두절) → 큐에 적재 후 복구 시 재전송, 서버 멱등 처리 (M-06)

### UF-D-05. 운행 종료 — 별도 조작 부재 (M-11 · RUN-05·06 · C-15)

최종 지점 도착 처리(UF-D-04) → 서버가 종료 판정 → `Run.status` = `finished` → 위치 송신 중단 → 관계자에 운행 종료 통지 · `run_ended` 발행

**기사가 누르는 종료 버튼은 부재.** 도착 처리 하나가 종료를 겸함.

| 구분 | 종료 시점 | 부수 효과 |
|---|---|---|
| 등원 | 학원(도착지) **도착 처리 즉시** | 전원 자동 `alighted` (C-07) |
| 하원 · 전원 하차 완료 | 마지막 승하차지 **도착 처리 즉시** | — |
| 하원 · 미하차 잔류 | **보류** — 마지막 탑승자가 `alighted` 되는 순간 서버 자동 전이 | 보류 중 `moving` 유지 · 미하차 목록 표시 (RUN-06) |

**분기 · 예외**

- (미하차 상태로 종료) → ✕ 성립 불가. 잔류가 0명이 되기 전에는 `finished` 미전이 — 기사 조작으로 우회할 경로가 부재
- (보류 중 위치 송신) → 계속 유지. `moving` 이므로 관제·학부모 화면에 버스가 계속 표시

### UF-E-02. 등원 승차 처리 (M-12 · BRD-01)

명단 → `[학생 선택]` → **사진 + 명단 육안 확인** → `[탑승]` → `PATCH /runs/{runId}/riders/{riderId}` → 서버 확인 → `waiting` → `boarded` → **5초 이내** 3곳 동시 반영: 학부모 승차 푸시 · 관계자 실시간 현황 · 알림 로그

**분기 · 예외**

- (일괄 처리) → 부재 — 개인별로만 (C-06)
- (기사 조작) → ✕ 403 — 동승자 전용
- (하원 회차) → 승차는 운행 시작 시 전원 자동 처리, 동승자는 하차만 담당 (UF-E-04)
- (서버 처리 실패) → "처리되지 않았습니다" 명시 · 상태 미변경 — 낙관적 UI 부재 (C-10)

### UF-E-03. 미승차 처리 · 에스컬레이션 (M-13 · EXC-01)

`[학생 선택]` → `[미승차]` → `no_show` → **T+0**: 학부모 즉시 알림 + 관계자 동시 통지 + **3분** 카운트다운 시작(학원별 설정) → T+0~3분 대기 → 무응답 시 `[보호자 전화 시도]`(시도 이력 저장) → **T+3분** 무응답 확정 → 관계자 에스컬레이션 보고 → 관계자 판단에 따라 출발

**분기 · 예외**

- (`absent` 와의 구분) → `absent` 는 학부모 사전 OFF 로 명단에 부재. 동승자가 누르는 것은 나올 예정이던 학생의 `no_show` (C-02)
- (학부모 응답 도착 — 전화·앱) → 카운트다운 중단 → 현장 판단으로 처리
- (`no_show` 전이) → 종결 상태 — 이후 `boarded` 로 진행 부재. 오조작은 되돌리기로 처리 (UF-E-06)
- (알림 off 설정 학부모) → 푸시만 차단, 목록·로그에는 존치
- (기록) → 대기 시작·종료 시각, 연락 시도 이력, 최종 판단(출발/재시도) 저장

### UF-E-04. 하원 하차 처리 · 보호자 부재 (M-12 · M-14 · EXC-02)

운행 시작 시 전원 자동 `boarded` → 승하차지 도착 → `[학생 선택]` → 혼자 귀가 가능 여부 확인 → `[하차]` → `alighted` → 학부모 하차 푸시 + 관계자 현황 + 로그

**분기 · 예외**

- (혼자 귀가 불가 · 보호자 부재) → `[보호자 부재 보고]` → `POST /runs/{runId}/reports` → 관계자 즉시 통지 → 관계자 판단

- (미하차 상태) → 운행이 `finished` 로 전이하지 않고 보류 — 마지막 학생 하차 시 서버가 자동 종료 (UF-D-05)

### UF-E-05. 지연 알림 전송 — **동승자 전용** (M-05 · NTF-06)

- (수신 설정) → 지연 알림은 설정 항목 자체가 부재 — 대상자 전원 수신 (NTF-07)
- (`absent` 학생) → 발송 대상에서 제외 (C-02)
- (기발송 후 추가 지연) → 누적/갱신 규칙 미확정 (PRD §10.1 오픈 이슈 I)

### UF-E-06. 상태 되돌리기 (BRD-05)

## 6.5 크로스롤 — 비상 알림

### UF-X-08. 비상 알림 — 발신부터 확인까지 (M-15 · A-16 · O-07 · EXC-04)

**기사·동승자 공통.** 승하차와 달리 역할을 제한하지 않음 — 안전 사안.

운행 화면 `[비상]` → `[유형 선택]`(사고 · 차량 고장 · 학생 응급 · 기타) → `[메모 입력]`(선택) → `POST /runs/{runId}/emergency` → 현재 위치·회차·호차·인력 연락처 자동 첨부 → **학원 관계자 + 메인 관리자에 동시 발송**(팝업 · on/off 부재) → 관계자 `[확인]` → 발신자 앱에 "학원이 확인했습니다" 표시

**분기 · 예외**

- (수신 범위) → 학원 관계자 · 메인 관리자. **학부모·학생은 대상 밖** — 안내 시점·문구는 사실을 파악한 관계자가 판단 (C-17)
- (발신 가능 시점) → 회차가 `confirmed` 이후면 가능. **운행 중이 아니어도 발신 가능** — 출발 전 차량 이상이 대상
- (오발신) → 발신 후 **1분 이내** 취소 가능. 취소 사실도 수신자에게 통지되고 **이력은 존치** — 발신 기록 자체를 지우지 않음
- (관계자 미확인) → 메인 관리자 콘솔에 **미확인 상태와 경과 시간** 노출. 관계자 1명 체제라 그의 부재가 곧 공백
- (통신 두절) → 오프라인 큐 적재 후 복구 시 전송. **전송 시각과 발신 시각을 함께 기록** — 사고 시점 판정 근거
- (중복 발신) → 차단 부재. 같은 회차에 여러 건이 쌓이면 목록으로 표시 — 상황이 바뀔 때마다 다시 알리는 것이 정상

## 7. 학원 관계자 플로우

### UF-M-01. 가입 요청 승인 · 레코드 연결 (A-02 · AUTH-10·11)

### UF-M-02. ②구간 변경 승인 · 거절 (A-05 · REQ-04·05)

푸시 즉시 수신 → `[승인 대기 목록]` → `GET /staff/approvals` → `[요청 선택]` → 승인 화면 — 출발까지 **남은 시간 카운트다운** · 요청 학생·승하차지 · 잔여 인원 · 영향 학생 · 정원 · **기존 노선 vs 재최적화 결과 대조**(순서 변경 · 제거되는 승하차지 · 전/후 예상 소요시간·거리) → `[차이 확인]` → `[승인]` → `POST /staff/approvals/{id}/decide` → `absent` 처리 + **재최적화 노선 배포** → 기사·동승자 푸시(확인 응답 대상) + 학부모 통보 → 처리 이력 저장(누가·언제·무엇·자동 거절 여부·배포 노선 버전)

**분기 · 예외**

- (승인 효과 범위) → `absent` 처리 + **노선 재최적화·재배포**. 출발 전이라 주행 중 위험이 부재하고 기사·동승자가 확인 응답을 다시 함 (C-04 ② · A-05)
- (잔여 인원 0명) → 해당 승하차지가 **재최적화로 노선에서 제거** — 출발 전이라 `skipped` 표시가 아니라 노선 자체가 갱신 (C-05 대비 지점)
- (거절) → 사유와 함께 학부모 통보 · **기존 경로 유지**, 재최적화 부재
- (출발 시각 도달 또는 운행 시작 · 미처리) → ✕ 서버가 자동 거절 — **기존 노선 유지**(재최적화 부재) + 학부모 통지 · 횟수 미소진
- (승인 조작이 마감 이후 도달) → ✕ 반영 부재 — 이미 자동 거절로 종결, 기존 노선 유지
- (책임 소재) → 승인한 관리자 — 이력 저장이 전제
- (이른 아침 미접속) → 요청이 `pending` 으로 잔류하다 자동 거절로 종결 (X-02 미해결)

### UF-M-03. 노선 강제 추가 — ①구간 한정 (A-06 · RTE-06)

학부모 전화 접수 "오늘만 B 승하차지" → `[운행 관리 · 강제 추가]` → `[기존 학생 검색·연동]`(신규만 직접 입력) → `[주소 입력]` → 주소 검증(좌표 변환) → 승하차지 매칭 또는 신규 생성 → `[추가할 호차 선택]` → `POST /staff/runs/{runId}/forced-add` → 노선 재최적화 → 기사·동승자 배포 + 푸시 → 반영 상태 확인 화면

**분기 · 예외**

- (②구간 진입 = 출발 30분 안쪽) → ✕ 추가 차단 — **관계자도 예외 부재**
- (주소 검증 실패) → ✕ 저장 보류 + 재입력 요구
- (정원 초과) → ✕ 저장 차단 — 학생 탑승 가능 인원 = 정원 − 기사 − 동승자 (BUS-04)
- (기존 학생을 이름으로 직접 입력) → 중복 레코드 생성 위험 — 검색·연동 경로가 기본
- (적용 범위) → 당일 운행에만. 고정 노선 불변

### UF-M-04. 수동 조정 · 버스 간 이동 (A-07 · RTE-07)

`[학생 선택]` → `[출발 버스 명단에서 제외]` → `[도착 버스에 강제 방문지 추가]` 또는 `[근처 기존 승하차지 명단에 추가]` → `POST /staff/students/{id}/transfer` → **양쪽 노선 모두 재최적화** → 양쪽 영향 표시 → 양쪽 기사·동승자에 배포 + 푸시

- (파급 범위) → 학생 1명 이동으로 출발 버스·도착 버스 노선이 둘 다 변경 — 양쪽 영향을 한 화면에 표시

- (구간 제약) → ①구간에서만. ②구간 이후는 추가에 해당하여 차단

- (운행 종료 후) → 금일 현황에서 미승차 인원·처리 이력 확인

### UF-M-06. 기초 데이터 관리 (A-08~A-12)

**학생 등록** — `[학생 정보 관리]` → `[추가]` → 이름 · **사진** · 성별 · 나이(학년) · 반 · **특이사항** · 혼자 귀가 가능 여부 · 좌석 → `[저장]`

- (**보호자 연락처는 입력하지 않음**) → 학부모 계정이 연결되면 그 계정의 연락처를 표시. 중복 입력이 없으므로 보호자가 번호를 바꾸면 자동 반영
- (**승하차 주소도 입력하지 않음**) → 학부모가 요일별 주소(P-05)·일일 승하차지(P-06)로 등록하고 그 시점에 검증·매칭. 관계자는 조회만
- (계정 미연결 상태) → 학생 레코드만 존재하고 **연락처·주소가 비어 있음** — 학부모 가입 승인으로 연결돼야 명단이 완성 (UF-M-01)
- (퇴원) → soft delete — 오늘 명단은 유지, 과거 이력 보존

**차량 등록** — `[차량 관리]` → `[추가]` → **호차명 · 차량번호 · 정원** → `[저장]`

- (**학생 탑승 가능 인원은 입력하지 않음**) → **배차 시 자동 계산** — 정원 − 배치된 기사 − 배치된 동승자
- (배정이 계산값 초과) → ✕ 차단 (BUS-04)

**매니저 관리 · 배치** — `[매니저 관리]` → `[추가]` → 이름 · 연락처 · 근무 시간 · 역할(기사/동승자) → `[저장]` → `[운행 관리 · 회차 선택]` → `[기사 배치]` → `PATCH /staff/runs/{runId}/assignment`

- (근무 시간과 운행 시간 불일치) → 경고 표시
- (동일 매니저 시간 중복 배치) → 충돌 검출·경고 (MGR-06)
- (배치 중인 매니저 삭제) → ✕ 차단 — 배치 해제 후 삭제
- (당일 배치 변경) → 해당 매니저 앱에 즉시 반영 + 푸시

**운행 스케줄** — `[운행 스케줄]` → 요일·시간별 운행 계획 등록 → 일일 회차 자동 생성 (SCH-01·02)

- (휴원·특강) → 회차 임시 추가·취소로 처리 — **정규 스케줄은 불변** (SCH-03)

**고정 노선 관리** — `[고정 노선]` → 학생 요일별 주소 기반 노선 편성·최적화 → 배치 매니저 표시 (RTE-01)

- (확정 노선과의 관계) → 별개. 확정 노선은 출발 30분 전 배치가 산출 (UF-X-05)

### UF-M-08. 경유 지점 지정 (A-15 · RTE-10)

**분기 · 예외**

- (미리보기 단계) → 대조를 확인하고 `[배포]` 를 누르기 전까지 확정 노선은 불변 — 지정 즉시 배포 부재
- (③구간 · 운행 시작 후) → ✕ 지정 불가 — 노선 잠금 (C-04 ③)
- (주소 검증 실패) → ✕ 저장 보류 + 재입력 안내 (STU-05)

| 당일 ~ 출발 30분 전 | 학부모 | 하원 회차 탑승 OFF · 하차 위치 변경 (UF-P-04·06) | `absent` 기록 또는 승하차지 변경 + 재최적화 |
| **출발 30분 전** | 시스템 | 확정 배치 실행 (UF-X-05) | 하원 확정 노선 배포 · `confirmed` |
| 30분 안쪽 ~ 출발 전 | 학부모 → 관계자 | ②구간 OFF 신청 → 승인 (UF-P-05 · UF-M-02) | 재최적화·재배포 · **하원 회차의 한도 1회**(등원 회차와 별개) |
| **출발 시각 ±3분** | 기사 | 운행모드 시작 (UF-D-03) | **전원 자동 `boarded`** · 노선 잠금 · 위치 송신 시작 |
| 승하차지 접근 중 | 시스템 | 위치 기반 이벤트 판정 | "곧 도착합니다" 예고 알림 자동 발송 |
| 승하차지 진입 직전 | 기사 | 도착 처리 (UF-D-04) | 포인터 전진 |
| 승하차지에서 | 동승자 | 혼자 귀가 가능 여부 확인 → 개인별 하차 (UF-E-04) | `alighted` · 학부모 하차 푸시 + 관계자 현황 |
| 보호자 부재 시 | 동승자 | 보호자 부재 보고 (UF-E-04) | 관계자 즉시 통지 → 관계자 판단 |
| 최종 승하차지 | 기사 | **도착 처리 = 종료** (UF-D-04·05) | 전원 하차면 즉시 `finished`. 미하차 잔류 시 **종료 보류** + 목록 표시 |
| 잔류 해소 후 | 동승자 → 기사 | 하차 처리 완료 → 종료 재시도 | `finished` · 관계자 통지 |

**등하원 비대칭 요약 (C-07)** — 등원 = 승하차지별 **승차** 처리 + 종료 시 전원 자동 하차 / 하원 = 시작 시 전원 자동 승차 + 승하차지별 **하차** 처리.

## 12. 실패 · 예외 경로 모음

### 12.1 서버 처리 실패 (C-10)

| 발생 지점 | 처리 |
|---|---|
| 탑승 토글 · 변경 신청 | 기존 상태 복구 · "처리되지 않았습니다" 명시 · ②구간 **횟수 미소진** — 재신청 가능 |
| 승하차 처리 | 상태 미변경 · 알림 미발송 · 재시도 유도. 낙관적 UI 부재 |
| 요일별 주소 저장 | 기존 값 유지 · 실패 명시 |
| 공통 원칙 | 서버 2xx 확인 후에만 "처리되었습니다" 표시 — 실패가 조용히 넘어가는 경로 부재 |

### 12.2 통신 두절

| 대상 | 처리 |
|---|---|
| 동승자 승하차 처리 | 로컬 큐 적재 → 복구 시 자동 재전송 → 서버 멱등 처리 (UF-E-07) |
| 기사 도착 처리 · 위치 송신 | 큐 적재 후 재전송. 학부모 화면은 "마지막 확인 위치 · N분 전" |
| 명단 조회 | 로컬 캐시로 계속 조회 가능 |
| 학부모 실시간 위치 | 신호 유실 표기 — 위치 갱신 중단이 오류 화면으로 이어지는 경로 부재 |

### 12.3 승인 무응답 · 한도 소진

| 상황 | 처리 |
|---|---|
| ②구간 요청이 마감(출발 시각 · 운행 시작 중 먼저) 까지 `pending` | 서버가 **자동 거절** + **기존 노선 유지** + 학부모 통지 · 횟수 미소진 (X-02) |
| 같은 회차에 ②구간 변경 2회째 시도 | ✕ "금일은 변경할 수 없습니다" — 회차당 1회 (다른 회차의 한도는 미소진) |
| 가입 요청 장기 미처리 | 계정 `PENDING` 잔류 — 승인 대기 화면 고정, 학원 문의처 안내 |

### 12.4 정원 · 중복 · 잔류

| 상황 | 처리 |
|---|---|
| 강제 추가 · 버스 간 이동 시 정원 초과 | ✕ 저장 차단 + 현재 인원·정원 병기 (BUS-04) |
| 차량 등록 시 배치 인원 초과 | ✕ 저장 차단 — 학생 탑승 가능 인원 = 정원 − 기사 − 동승자 |
| 동일 승하차지 도착 재처리 | ✕ 중복 차단 |
| 오프라인 큐 재전송 중복 | 멱등키로 중복 무시 |
| 하원 최종 도착 시 미하차 학생 존재 | 도착은 기록, **종료 보류** + 미하차 목록 표시. 잔류 0명 시 서버 자동 종료 (RUN-06 · C-15) |
| 승하차 오처리 | 되돌리기로 정정 · 이력 보존, 기발송 알림은 후속 처리 (UF-E-06) |

### 12.5 권한 · 구간 차단

| 상황 | 처리 |
|---|---|
| `PENDING` 계정의 일반 API 호출 | ✕ 서버 인가 계층 403 — 승인 대기 화면 · 로그아웃 2개만 허용 |
| `BLOCKED` 계정 로그인 | ✕ 실패 — 해제는 메인 관리자 (UF-O-03) |
| 기사의 승하차 상태 변경 시도 | ✕ 403 — 동승자 전용 (C-06) |
| 동승자의 운행 시작 · 종료 · 도착 처리 시도 | ✕ 403 — 기사 전용 |
| 출발 시각 ±3분 밖의 운행 시작 | ✕ 버튼 비활성 — 3분 초과 지연 시 대체 수단 부재 (X-01 미해결) |
| ③구간(운행 시작 후) 변경 시도 | ✕ 전면 불가 — 학부모·관계자 모두 |
| ②구간 추가 시도 | ✕ 차단 — 관계자도 예외 부재 |
| 동승자 당일 결근 | 승하차 기록 주체 부재 — 대체 프로세스 미정 (X-03 미해결) |
