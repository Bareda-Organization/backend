### 용어 · 역할 정의

| 용어 | 정의 |
|---|---|
| **인솔자** | 버스에 동승해 학생 승하차를 관리하는 인력. **승하차 상태 변경은 인솔자만 수행한다** |
| **버스기사** | 운전과 정류장 도착 처리를 담당. 승하차 상태는 변경하지 않는다 |
| **매니저** | 버스기사 + 인솔자를 포괄하는 운행인력 총칭 |
| **학원 관계자** | 학원당 **1명**. 명단·노선·인력 관리 전권을 가진다 |
| **메인 관리자** | 서비스 운영사. 학원 등록과 관계자 계정 발급을 담당 |

### 탑승 상태 정의

| 코드 | 라벨 | 발생 경로 | 알림 |
|---|---|---|---|
| `waiting` | 대기 | 초기값 | — |
| `boarded` | 탑승 완료 | 인솔자가 처리 | 학부모에게 승차 알림 |
| `alighted` | 하차 완료 | 인솔자 처리(하원) / 자동(등원) | 학부모에게 하차 알림 |
| `absent` | **미등원** | 학부모가 **사전에** 탑승 OFF | 관계자에게 통지 (학부모 알림 없음) |
| `no_show` | **미승차** | 정류장에 나오지 않아 **현장에서** 처리 | 학부모에게 즉시 미승차 알림 |

> `absent`와 `no_show`는 반드시 구분한다. 전자는 학부모가 미리 알린 정상 상황이고, 후자는 예정된 아이가 나오지 않은 이상 상황이다. 알림 대상도 후속 조치도 완전히 다르다.

## 1. AUTH — 인증 · 계정

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| AUTH-01 | 회원가입 | 학부모·학생·버스기사·인솔자가 form 방식으로 계정을 생성한다. 아이디·비밀번호 등 기본 정보를 입력한 뒤 소속 학원을 선택하면 가입 요청이 생성된다. **가입 완료 = 이용 가능이 아니다.** 학원 관계자가 승인해야 계정이 활성화된다. 학원 관계자와 메인 관리자는 이 경로로 가입할 수 없다. |
| AUTH-02 | 소속 학원 선택 | 회원가입 과정에서 메인 관리자가 등록해 둔 학원 목록을 검색해 선택한다. 학원 코드와 학원명 양쪽으로 검색되며, 결과는 `{학원명} · {지역} · {학원 코드}` 세 값을 모두 표시해 동명 학원을 구분한다. 자유 입력이 아니라 목록 선택이므로 오탈자로 인한 미매칭이 발생하지 않는다. 비활성 학원은 검색 결과에서 제외되고, 목록에 없으면 "학원에 문의해 주세요"를 안내한다. |
| AUTH-03 | 승인 대기 상태 관리 | 가입 요청 후 관계자 승인 전까지 계정은 대기 상태(`PENDING`)를 유지한다. **로그인은 성공하되 볼 수 있는 화면은 승인 대기 안내 하나뿐이며**, 그 화면에 신청 학원명·지역·학원 코드·신청 일시·학원 문의처·로그아웃을 배치한다. 홈·명단·노선·실시간 위치·알림 목록·설정에는 접근할 수 없다. **차단은 화면 라우팅이 아니라 서버 인가 계층에서 수행하며, 대기 화면 조회와 로그아웃을 제외한 모든 API가 403을 반환한다.** 이 상태에서 수신하는 알림은 승인·거절 결과뿐이다. 거절되면 같은 화면에 사유를 표시하고 **학원을 다시 선택해 재신청할 수 있는 진입점**을 제공한다. 승인·거절 결과는 알림으로 통지한다. |
| AUTH-04 | 로그인 | 아이디·비밀번호로 로그인한다. 계정에 연결된 역할(학부모/학생/기사/인솔자/관계자/메인 관리자)에 따라 진입 화면과 접근 권한이 결정된다. 매니저 앱은 계정에 배정된 호차가 자동 결정되므로 사용자가 호차를 고르지 않는다. |
| AUTH-05 | 로그인 시도 횟수 제한 | 로그인 실패가 약 5회 누적되면 **해당 계정을 차단한다.** IP 단위 차단은 하지 않는다. 학원 와이파이나 한 가정에서 여러 계정을 쓰는 경우 무고한 사용자까지 잠기기 때문이다. 차단 시 사유와 해제 문의처를 안내하며 사용자 스스로 해제할 수 없다. |
| AUTH-06 | 로그인 차단 해제 | 메인 관리자가 차단된 계정 목록을 조회하고 해제한다. 차단 일시, 대상 계정, 소속 학원, 시도 횟수를 확인할 수 있으며 해제 처리자와 일시를 이력으로 남긴다. |
| AUTH-07 | 비밀번호 변경 | 사용자가 자신의 비밀번호를 변경한다. 학원 관계자 계정은 메인 관리자가 발급한 초기 비밀번호로 최초 로그인할 때 변경을 강제한다. |
| AUTH-08 | 아이디 · 비밀번호 찾기 | 아이디를 잊은 경우 가입 시 등록한 연락처로 확인하고, 비밀번호를 잊은 경우 본인 확인 후 재설정 링크 또는 임시 비밀번호를 발급한다. 관계자 계정은 메인 관리자가 직접 초기화한다. |
| AUTH-09 | 로그아웃 | 세션을 종료하고 로그인 화면으로 이동한다. |
| AUTH-10 | 가입 요청 승인 · 거절 | 학원 관계자가 자기 학원으로 들어온 가입 요청을 처리한다. 신청자 이름·역할·연락처·신청 일시를 확인하고 수락하거나 거절한다. **수락 시 반드시 계정을 실제 레코드에 연결해야 한다(AUTH-11).** 거절 시 사유를 입력해 통지하며, 미처리 건수는 내비게이션 배지로 표시한다. |
| AUTH-11 | 계정 ↔ 레코드 연결 | 승인 과정에서 계정을 실제 대상 레코드에 매칭한다. 학부모 계정은 학생 레코드에 **1:N으로 연결**하고(자녀가 여럿이면 연결을 여러 개 만든다), 학생 계정은 자기 학생 레코드에, 기사·인솔자 계정은 매니저 레코드에 연결한다. **동생이 나중에 등록되면 학부모가 다시 가입할 필요 없이 기존 계정에 연결만 추가한다.** **이 연결이 없으면 계정은 어떤 데이터도 볼 수 없다.** 관계자가 이름·연락처로 후보를 검색해 지정하며, 잘못 연결된 경우 재지정할 수 있다. |

## 2. ACAD — 학원 관리 (메인 관리자)

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| ACAD-01 | 학원 목록 · 검색 | 등록된 전체 학원을 조회한다. 학원명 또는 학원 코드로 검색하며, 목록에는 학원 코드·학원명·지역·관계자 계정 발급 여부·소속 사용자 수·활성 상태를 표시한다. |
| ACAD-02 | 학원 등록 | 새 학원을 등록한다. 학원 코드(고유값)·학원명·지역은 필수이며 주소·대표 연락처·내부 메모는 선택이다. 학원 코드가 중복되면 저장을 차단한다. 학원명과 지역이 모두 같으면 분원일 수 있으므로 경고만 표시하고 저장은 허용한다. 등록된 학원은 회원가입 화면의 검색 대상이 된다. |
| ACAD-03 | 학원 정보 수정 | 학원의 코드·이름·지역·연락처를 수정한다. 학원 코드를 변경해도 기존 가입자의 소속은 내부 식별자로 연결되어 있어 영향받지 않으며, 이 사실을 화면에 안내한다. |
| ACAD-04 | 학원 비활성화 | 계약 종료 등의 사유로 학원을 비활성화한다. 회원가입 검색 결과에서 제외되고 신규 가입 요청이 차단되지만 **기존 사용자의 로그인은 유지된다.** 운행 중 로그아웃되면 명단 조회가 불가능해 안전 사고로 이어지기 때문이다. 물리 삭제는 하지 않는다. |
| ACAD-05 | 학원 관계자 계정 생성 | 학원 관계자 계정을 직접 발급한다. **학원당 관계자는 1명**이므로 이미 계정이 있는 학원에는 추가 발급을 차단한다. 소속 학원·담당자 이름·연락처·로그인 아이디를 입력하면 초기 비밀번호가 자동 생성되며, 결과 다이얼로그에서 확인해 학원에 전달한다. |
| ACAD-06 | 학원 관계자 계정 관리 | 발급된 관계자 계정의 이름·연락처를 수정하고 비밀번호 초기화·비활성화·삭제를 수행한다. 담당자가 바뀌면 기존 계정을 비활성화하고 새로 발급한다. 관계자 계정은 학생 개인정보 전체에 접근하므로 퇴사 시 즉시 권한을 회수해야 한다. |

## 3. STU — 학생 관리 (학원 관계자)

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| STU-01 | 학생 목록 · 검색 | 학원에 등록된 학생을 조회한다. 이름으로 검색하며 목록에는 이름·반·배정 호차·탑승 정류장·보호자 연락처를 표시한다. |
| STU-02 | 학생 등록 | 신규 학생을 등록한다. 이름·보호자 전화번호는 필수이고 영문 이름·생년월일·반·주소·특이사항은 선택이다. 요일마다 하원 위치가 다르면 요일별 하원 주소를 추가한다. 저장 시 주소를 검증해 노선에 반영한다. |
| STU-03 | 학생 정보 수정 | 등록된 학생의 개인정보를 수정한다. 주소를 변경하면 정류장 매칭이 다시 수행되어 노선에 반영된다. |
| STU-04 | 학생 삭제 (퇴원 처리) | 퇴원한 학생을 명단에서 제외한다. 확인 다이얼로그를 거치며, 삭제하면 **오늘 이후** 운행 명단에서 빠지고 연결된 계정은 로그인할 수 없게 된다. 오늘 운행 명단에는 그대로 남는다. soft delete로 처리해 과거 탑승 이력을 보존한다. |
| STU-05 | 주소 검증 및 정류장 매칭 | 학생 등록·수정 및 노선 강제 추가 시 입력한 주소를 검증한다. 주소를 좌표로 변환하고 유효성을 확인한 뒤 가까운 기존 정류장에 매칭하거나 신규 정류장을 생성해 노선에 반영한다. 검증되지 않은 주소는 저장을 보류한다. |
| STU-06 | 요일별 하원 위치 관리 | 기본 하원 위치 외에 특정 요일에만 적용되는 하원 주소를 등록·수정한다. "수요일은 할머니 집에서 하원" 같은 반복 패턴을 노선 편성에 반영한다. 여러 건 등록할 수 있다. |
| STU-07 | 특이사항(비고) 관리 | 학생별 운영상 유의사항을 자유 텍스트로 기록한다. 이 값은 관계자 웹의 호차별 명단과 매니저 앱의 탑승자 명단에 함께 노출되어 현장에서 확인된다. |
| STU-08 | 혼자 귀가 가능 여부 설정 | 하원 시 보호자 없이 학생을 내려도 되는지를 학생별로 설정한다. 인솔자의 하차 처리 화면에 이 값이 표시되어 판단 근거가 된다. 혼자 귀가가 허용되지 않은 학생인데 보호자가 보이지 않으면 예외 상황(EXC-02)으로 처리한다. |

## 4. BUS — 차량 관리 (학원 관계자)

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| BUS-01 | 차량 목록 조회 | 학원이 운영하는 버스(호차)를 조회한다. 호차 번호·차량번호·정원·학생 탑승 가능 인원·배치된 노선·운행 가능 여부를 표시한다. |
| BUS-02 | 차량 등록 | 새 버스를 등록한다. 호차 번호와 차량번호, 승차 정원을 입력한다. **학생 탑승 가능 인원 = 승차 정원 − 기사 − 인솔자**로 자동 계산되며 이 값이 정원 검증의 기준이 된다. |
| BUS-03 | 차량 정보 수정 | 차량번호·정원·운행 가능 여부를 수정한다. 정원을 줄였을 때 이미 배정된 인원이 초과하면 경고한다. |
| BUS-04 | 정원 초과 검증 | 노선 편성·강제 추가·수동 조정 시 해당 버스의 학생 탑승 가능 인원을 넘는지 검사한다. 초과하면 저장을 차단하고 현재 인원과 정원을 함께 표시한다. |

| MGR-06 | 배치 충돌 검증 | 근무 시간과 운행 시각이 맞지 않거나 동일 매니저가 시간이 겹치는 두 노선에 배치되는 경우를 검출해 경고한다. |

## 7. RTE — 노선 관리

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| RTE-01 | 고정 노선 관리 | 학기 단위로 유지되는 기본 노선을 관리한다. 버스별 노선과 노선별 정류장 리스트를 정류장 단위로 편성하며 배치된 기사·인솔자를 함께 표시한다. 신규 학생 유입이나 연초 등 필요한 시점에 관계자가 갱신한다. |
| RTE-02 | 당일 노선 확정 | 각 회차의 출발 **60분 전**에 그날 운행할 노선을 확정한다. **확정 시점의 최신 탑승 의사(ATT)와 승인된 위치 변경을 읽어** 산출하며, 확정 전에는 기사·인솔자가 명단에 진입할 수 없다. 확정된 노선은 기본 노선과 별개로 관리한다. 배치가 지연 실행되면 **60분 전 스냅샷이 아니라 실행 시점의 최신 값을 읽는다.** 단 추가·삭제 가능 여부의 판정 기준은 배치 실행 시각이 아니라 언제나 `출발 시각 - 60분`이다. |
| RTE-03 | 노선 변경 구간 규칙 | 변경 가능 범위를 세 구간으로 통제한다. 출발 60분 이전에는 추가·삭제가 모두 가능하고 즉시 반영된다. 59분 59초부터 운행모드 시작 전까지는 **삭제만 가능하며 관리자 승인을 거쳐야 반영된다.** 운행모드를 시작한 이후에는 어떤 변경도 불가능하다. |
| RTE-04 | 탑승자 삭제 처리 | 삭제가 확정되면 해당 정류장의 잔여 탑승자 수를 재계산한다. 다른 탑승자가 남아 있으면 해당 인원만 명단에서 빼고 정류장은 그대로 경유한다. 그 학생이 혼자였다면 정류장 자체를 삭제해 미경유로 전환한다. 삭제할 때마다 판정을 다시 수행한다. |
| RTE-05 | 미경유 정류장 처리 | 잔여 탑승자가 0명이 된 정류장을 미경유로 표시한다. **노선을 재최적화하지 않으며** 실제 주행 경로는 기사가 최단거리로 판단해 패스한다. 시스템은 미경유 정류장을 표시하고 다음 경유 정류장을 안내하는 것까지만 담당한다. 마지막 정류장이어도 동일하며 뒤 정류장의 도착 예정 시각도 재계산하지 않는다. |
| RTE-06 | 노선 강제 추가 | 이머전시 상황에서 관계자가 오늘 운행에만 탑승자를 추가한다. 기존 학생은 검색해서 계정을 연동하고 신규는 직접 입력하며, 주소는 검증을 거쳐 노선에 반영된다. **고정 노선은 바뀌지 않는다.** 추가 후 반영 상태를 확인할 수 있고 호차별로 서로 다른 노선에 각각 추가할 수 있다. 정원 초과 시 차단한다. |
| RTE-07 | 수동 학생 조정 · 버스 간 이동 | 편성 결과를 관계자가 수동으로 조정한다. 학생을 다른 버스로 옮기면 기존 버스의 정류장 명단에서 제외하고, 신규 버스에 강제 방문지를 추가하거나 근처 정류장이 있으면 그 명단에 넣는다. 학생 한 명을 옮겨도 **출발 버스와 도착 버스의 노선이 둘 다 바뀌므로** 양쪽 영향을 함께 표시한다. |
| RTE-08 | 노선 변경분 하이라이트 | 확정 이후 발생한 변경을 색으로 구분한다. 추가된 탑승자·정류장은 초록, 삭제된 탑승자는 빨강, 미경유 정류장은 빨강 취소선이다. 미경유 정류장은 목록에서 제거하지 않고 취소선으로 남기며 순서 번호도 재부여하지 않는다. |
| RTE-09 | 노선 최적화 | 출발 60분 이전 구간에서 변경분을 반영해 노선을 다시 계산한다. 탑승 정원, 정류장별 정차 시간, 학원 도착 마감, 도로 제약 등을 고려한다. **알고리즘 기준은 보류 상태**이며 별도 확정이 필요하다. |

## 8. REQ — 변경 요청 · 승인

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| REQ-01 | 탑승 위치 변경 신청 | 학부모가 자녀의 승·하차 정류장을 바꿔달라고 신청한다. 변경할 요일, 탑승 정류장, 상세 주소, 사유를 입력한다. 위치 변경은 내부적으로 삭제와 추가를 동시에 수행하므로 **출발 60분 이내에는 신청할 수 없다.** 60분 이전 신청은 검증을 통과하면 즉시 반영된다. |
| REQ-02 | 탑승 취소 신청 | 학부모가 특정 회차의 탑승만 취소한다. **60분 이전 신청은 즉시 반영되고, 60분 이내 신청은 관리자 승인을 거쳐야 반영된다.** 운행모드 시작 이후에는 신청할 수 없다. 위치 변경과 별개 버튼으로 분리해 노출한다. |
| REQ-03 | 변경 신청 상태 조회 | 학부모가 자신이 낸 신청의 처리 상태를 확인한다. 반영 완료·승인 대기·거절(사유 표시) 상태를 표시하며, 승인 대기 중에는 기존 정류장에서 탑승하도록 안내한다. 상태가 바뀌면 알림을 발송한다. |
| REQ-04 | 60분 이내 변경 승인 · 거절 | 관계자가 출발 60분 이내에 접수된 탑승 취소 요청을 검토해 처리한다. 요청 학생, 정류장, 잔여 인원, **삭제 시 해당 정류장이 미경유로 전환되는지 여부**를 함께 표시한다. 운행 시작이 임박한 시점의 판단이므로 승인 화면에 남은 시간을 노출한다. **책임 소재가 승인한 관리자에게 있으므로** 누가·언제·무엇을 승인했는지 이력을 저장한다. |
| REQ-05 | 승인 대기 알림 | 60분 이내 요청이 접수되면 관계자에게 즉시 알린다. 출발이 임박한 상황이라 늦게 확인하면 승인 자체가 무의미해지므로, 목록 배지가 아니라 푸시로 통지한다. |

## 9. ATT — 등하원 탑승 의사

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| ATT-01 | 등하원별 탑승 여부 설정 | 학부모가 회차별로 자녀의 버스 탑승 여부를 켜고 끈다. 등원과 하원을 별개 개념으로 관리하는 것이 아니라 **예정된 노선 중 빠른 회차(등원)와 늦은 회차(하원)를 각각 on/off** 하는 방식이다. 기본값은 둘 다 ON이며 선택 즉시 저장된다. 버스로 등하원하지 않는 케이스는 관리 대상이 아니다. |
| ATT-02 | 탑승 의사의 노선 반영 | 회차를 OFF로 바꾸면 상태가 **미등원(`absent`)** 으로 기록되고 **기사·인솔자 명단에서 제외된다**(회색 표시로 남기지 않는다). 확정 노선의 승차 인원이 줄어 정류장 잔여 인원이 0명이 되면 미경유로 전환된다. 변경 마감은 노선 변경 구간 규칙(RTE-03)을 따르므로 60분 이내 OFF는 관리자 승인을 거친다. |
| ATT-03 | 다자녀 스케줄 관리 | **한 계정에 자녀 N명을 연결하는 방식이다**(자녀별 계정을 만들어 묶지 않는다). 자녀가 2명 이상일 때만 홈에 자녀 선택 UI를 노출하고, 선택된 자녀 기준으로 운행 정보·상세 노선·지도·탑승 토글·위치 변경이 전환된다. 자녀마다 호차·노선·정류장이 각각 다를 수 있다. **단 알림은 자녀 선택과 무관하게 연결된 모든 자녀의 것을 수신하며, 모든 알림 문구에 자녀 이름을 포함한다.** |

## 10. RUN — 운행 실행 (매니저 앱)

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| RUN-01 | 담당 운행 노선 조회 | 기사·인솔자가 오늘 담당할 회차 목록을 확인한다. 회차별 상태, 호차, 구분, 출발 시각, 정류장 수, 탑승 예정 인원, 배치된 기사·인솔자, 추가·삭제 인원 배지를 표시한다. 확정 전 회차는 확정 예정 시각만 안내하고 진입을 막는다. |
| RUN-02 | 운행모드 시작 | 기사가 운행을 개시한다. 이 버튼을 누르는 순간 회차 상태가 운행 중으로 바뀌고 **모든 노선 변경이 잠긴다.** 동시에 실시간 위치 송신이 시작되어 학부모·학생·관계자 화면에 버스가 나타난다. 하원 회차는 이 시점에 탑승자 전원이 자동으로 탑승 완료 처리된다. |
| RUN-03 | 운행모드 화면 | 운전 중 사용하는 최소 정보 화면이다. 현재 이동 중인 정류장과 다음 정류장을 대형 텍스트로 표시하고 각각을 누르면 해당 정류장 탑승자 명단이 열린다. 정류장 도착 처리·지연 알림 전송·운행 종료 버튼을 대형 타깃으로 배치한다. 테마와 무관하게 항상 어둡게 표시하며 정류장 주소에서 외부 내비게이션 앱으로 이동할 수 있다. 다음 정류장이 미경유면 실제로 들를 다음 정류장을 대신 표시한다. |
| RUN-04 | 정류장 도착 처리 | 기사가 정류장 **도착 직전**(진입 1~2분 전)에 도착을 처리한다. **이 액션이 해당 정류장 탑승자 보호자에게 도착 알림을 발송하는 유일한 트리거이며, 알림은 "곧 도착합니다" 예고형이다.** 처리하면 현재 정류장 포인터가 다음 정류장으로 넘어가고 전송 결과를 배너로 피드백한다. **단 인솔자의 승하차 처리 대상 명단은 처리가 끝날 때까지 계속 열려 있어야 한다** — 기사의 포인터와 인솔자의 작업 대상은 별개다. 같은 정류장에 대한 중복 처리는 차단한다. 도착 처리부터 실제 도착까지 걸린 시간을 로그로 남긴다. |
| RUN-05 | 운행 종료 | 최종 학원 도착 이후 기사가 운행을 종료한다. **등원 회차는 이 시점에 탑승자 전원이 자동으로 하차 완료 처리된다.** 회차 상태가 종료로 바뀌고 위치 송신이 멈추며 관계자에게 종료 결과가 전송된다. |
| RUN-06 | 잔류 학생 검증 | 운행 종료 시 탑승 완료 상태로 남아 있는 학생이 있는지 확인한다. **하원 회차에서만 실질적으로 동작한다** — 정류장에서 내리지 않은 학생이 있으면 목록을 표시하고 운행 종료를 차단한다. 등원 회차는 학원 도착과 함께 전원 하차 처리되므로 차단 대상이 아니다. |
| RUN-07 | 노선 변경 확인 응답 | 확정 이후 노선이 바뀌면 기사·인솔자가 변경 내용을 확인했다는 응답을 남긴다. 무엇이 추가·삭제됐는지 목록으로 보여주고 확인 버튼을 누르게 하며, 미확인 상태는 관계자 화면에 표시된다. 색 표시만으로는 실제로 봤는지 알 수 없기 때문이다. |

## 11. RST — 탑승자 명단

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| RST-01 | 정류장 리스트 조회 | 기사·인솔자가 담당 노선의 정류장을 운행 순서대로 확인한다. 정류장을 누르면 해당 정류장의 탑승자 명단이 열린다. 추가된 정류장은 초록, 미경유 정류장은 빨강 취소선으로 표시하고 미경유 안내 문구를 함께 노출한다. 하단에 운행모드 바로가기 버튼을 고정 배치한다. |
| RST-02 | 정류장별 탑승자 명단 | 특정 정류장에서 타거나 내리는 학생 명단을 조회한다. **미등원(`absent`) 학생은 이 명단에 표시하지 않는다** — 기사·인솔자가 세는 인원 수가 실제와 어긋나면 안 되기 때문이다. 개인 단위가 아니라 **정류장 단위로 학생을 묶어** 보여준다. **등원 회차는 승차 명단, 하원 회차는 하차 명단**으로 성격이 다르다. 학생 이름·반·보호자 연락처(마스킹)·특이사항·혼자 귀가 가능 여부·현재 상태를 표시하며 당일 추가된 탑승자는 하이라이트한다. |
| RST-03 | 호차별 일일 탑승자 명단 | 관계자가 특정 호차의 오늘 탑승자 전체를 조회한다. 학생·반·정류장·보호자 연락처·변경 구분·상태·비고를 표로 확인하며 추가된 탑승자는 초록, 삭제된 탑승자는 빨강으로 구분한다. 정류장 고정 인원과 임시 추가 인원이 함께 표시된다. |
| RST-04 | 명단 집계 | 정류장 또는 회차 단위로 탑승 완료·대기·미승차·미등원 인원을 실시간 집계해 표시한다. **미등원 학생은 개인 행이 명단에서 빠지지만 집계에는 `미등원 N명`으로 숫자가 남는다.** 상태 변경이 발생할 때마다 즉시 갱신된다. |

## 12. BRD — 승하차 처리 (인솔자)

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| BRD-01 | 개인별 승차 처리 | **인솔자가** 학생 한 명씩 탑승 여부를 처리한다. 태그나 비콘 없이 앱에서 수동으로 누르는 방식이며, 탑승 또는 미승차 중 하나를 지정한다. **버스기사는 명단을 조회만 하고 상태를 바꿀 수 없다.** 운전 중인 사람이 명단을 조작하게 만들지 않기 위한 안전 설계다. 일괄 처리 기능은 제공하지 않는다. |
| BRD-02 | 개인별 하차 처리 | **하원 회차에서** 인솔자가 정류장별로 학생의 하차를 처리한다. 혼자 귀가가 허용되지 않은 학생은 화면에 표시가 뜨며, 보호자가 확인되지 않으면 예외 상황(EXC-02)으로 넘어간다. |
| BRD-03 | 등하원 자동 처리 | 등하원의 비대칭 구조를 시스템이 처리한다. **등원 회차**는 정류장별로 승차만 처리하고 학원 도착(운행 종료) 시 전원 자동 하차 처리한다. **하원 회차**는 학원 출발(운행모드 시작) 시 전원 자동 승차 처리하고 정류장별로 하차만 처리한다. 실제로 일어나지 않는 조작을 사용자에게 요구하지 않기 위한 것이다. |
| BRD-04 | 상태 변경 연쇄 처리 | 상태가 바뀌면 세 곳에 동시 반영된다. 학부모 앱에는 승차·하차·미승차 알림이 푸시되고, 관계자 웹의 실시간 탑승 현황이 갱신되며, 알림 로그에 종류별로 적재된다. **미등원(`absent`)은 학부모가 스스로 설정한 것이므로 학부모 알림을 보내지 않고 관계자에게만 통지한다.** |
| BRD-05 | 상태 되돌리기 | 잘못 누른 상태를 정정한다. 정정 시 이미 발송된 알림에 대한 후속 처리가 필요하며, 취소·수정 이력을 보존해 누가 언제 무엇을 바꿨는지 추적할 수 있어야 한다. |
| BRD-06 | 오프라인 처리 · 동기화 | 터널이나 지하주차장 등 통신이 끊긴 구간에서도 승하차 처리가 가능해야 한다. 상태 변경을 단말기에 먼저 기록하고 통신이 복구되면 서버로 자동 전송한다. 재전송 시 서버는 중복 처리를 무시해야 하며, 통신 두절 중에도 당일 노선·명단·긴급 연락처는 조회할 수 있어야 한다. |

## 13. EXC — 예외 상황

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| EXC-01 | 미승차 대기 · 에스컬레이션 | 예정된 학생이 정류장에 나오지 않았을 때의 처리 절차다. 인솔자가 미승차를 선택하면 학부모에게 즉시 알림이 발송되고 **기본 3분**의 대기 타이머가 시작된다. 대기 중 무응답이면 보호자에게 전화를 시도하고, **3분이 지나도 응답이 없으면** 학원 관계자에게 에스컬레이션 보고 후 관계자 판단에 따라 출발한다. **무응답 판정도 대기 시간과 같은 창을 쓴다.** 인솔자 화면에 남은 시간을 카운트다운으로 노출한다. **몇 분 기다리는지가 현장에서 가장 중요한 값**이므로 3분은 기본치이며 학원별 설정값으로 조정할 수 있다. 대기 시작·종료 시각, 연락 시도 이력, 최종 판단을 저장한다. |
| EXC-02 | 보호자 부재 처리 | 하원 시 지정된 위치에 보호자가 없고 학생이 혼자 귀가 대상이 아닐 때의 절차다. 인솔자가 보호자 부재를 등록하면 보호자에게 연락하고 설정된 시간만큼 대기한다. 연락이 되지 않으면 관계자에게 보고하고 학생을 다시 태운 채 운행을 계속한다. **최종 인계가 완료될 때까지 사건을 종료하지 않는다.** |
| EXC-03 | 현장 상황 보고 | 기사·인솔자가 운행 중 발생한 문제를 학원 관계자에게 보고한다. 도로 통제, 차량 이상, 사고, 예정에 없던 학생 탑승 요청 등 학부모 알림으로는 처리할 수 없는 사안을 다룬다. 보고 유형과 메모를 남기며 관계자에게 즉시 통지되고 처리 결과가 기록된다. **현재 시스템에는 기사·인솔자에서 학원으로 향하는 소통 경로가 이것뿐이므로 반드시 필요하다.** |

## 14. LOC — 위치 · 지도

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| LOC-01 | 실시간 위치 송신 | 운행 중인 차량의 GPS 위치를 주기적으로 서버에 전송한다. 운행모드 시작과 함께 송신이 시작되고 운행 종료와 함께 멈춘다. 신호가 잡히지 않는 구간에서는 마지막 수신 위치와 경과 시간을 보존한다. |
| LOC-02 | 실시간 버스 위치 조회 | 학부모·학생이 자녀가 타는 버스의 현재 위치를 지도에서 확인한다. **다자녀는 선택된 자녀가 타는 버스를 보여준다** — 형제가 서로 다른 호차일 수 있다. 버스 마커와 노선, 정류장 순서를 표시한다. **도착 예정 시간은 표시하지 않고 위치만 보여준다.** 다른 학생의 탑승 인원 등 개인정보성 상세 내역도 노출하지 않는다. 위치 신호가 끊기면 "마지막 확인 위치 · N분 전"으로 표시한다. |
| LOC-03 | 상세 노선 조회 | 학부모·학생이 노선의 정류장 순서와 자기 탑승 정류장을 확인한다. 축약 지도와 정류장 타임라인, 배치된 기사·인솔자, 출발 시각을 표시한다. 정류장별 탑승 인원은 표시하지 않는다. 노선은 학원이 편성하며 학부모는 탑승 위치만 변경 신청할 수 있다는 안내를 노출한다. |
| LOC-04 | 지도 SDK 연동 | 실제 지도 타일과 경로 렌더링을 제공하는 외부 지도 SDK를 연동한다. 현재는 정류장 배열과 버스 진행률을 받는 인터페이스만 정의된 플레이스홀더 상태이며, 인터페이스를 유지한 채 내부 구현만 교체하는 것을 전제로 한다. |

## 15. NTF — 알림

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| NTF-01 | 승차 알림 | 학생 상태가 탑승 완료로 바뀌면 해당 학생의 보호자에게 발송한다. 승차 시각과 정류장을 포함한다. 설정에서 끌 수 있다. |
| NTF-02 | 하차 알림 | 학생 상태가 하차 완료로 바뀌면 해당 학생의 보호자에게 발송한다. 하차 시각과 정류장을 포함한다. 등원 회차의 자동 하차 처리 시에도 발송할지는 학원 정책에 따른다. 설정에서 끌 수 있다. |
| NTF-03 | 미승차 알림 | 학생 상태가 미승차로 바뀌면 해당 학생의 보호자에게 **즉시** 발송한다. 정류장과 시각을 포함하며 승차가 확인되지 않았음을 알린다. 학원 관계자에게도 동시 통지되고 **기본 3분**의 대기·에스컬레이션(EXC-01)이 시작된다. 미등원(`absent`)은 이 알림의 대상이 아니다. |
| NTF-04 | 버스 도착 알림 | **기사가 정류장 도착 처리(RUN-04)를 하면** 해당 정류장 탑승자의 보호자·학생에게 발송한다. 기사가 **도착 직전**에 처리하므로 문구는 **"{호차}가 {정류장}에 곧 도착합니다"** 예고형이다. 자동 트리거는 사용하지 않고 기사의 처리 액션 하나로 단일화한다. 미승차 확정 학생과 알림을 끈 사용자는 발송 대상에서 제외한다. 설정에서 끌 수 있다. |
| NTF-05 | 운행 시작 알림 | 회차가 운행 중 상태로 바뀌면 해당 회차 탑승자의 보호자에게 운행이 시작됐음을 알린다. 등하원 알림 설정에 귀속되어 함께 켜고 꺼진다. |
| NTF-06 | 도착 지연 알림 전송 | 기사·인솔자가 지연 사유와 지연 시간을 지정해 알림을 보낸다. 사유는 도로 정체·기상 악화·차량 점검·앞 정류장 대기 중에서 선택하고, 선택 시 메시지가 자동 생성되며 수정할 수 있다. 지연 시간은 5분 단위로만 선택한다. **현재 정류장 이후** 정류장의 탑승자 보호자에게만 발송되며 전송 전 미리보기를 제공한다. |
| NTF-07 | 알림 설정 | 학부모·학생이 알림 종류별로 수신을 켜고 끈다. 버스 도착 알림·등하원 알림·미승차 알림을 제어할 수 있고, **도착 지연 알림은 설정 항목 자체를 두지 않아 항상 발송된다.** 끈 알림도 앱 알림 목록에서는 확인할 수 있으므로 on/off는 푸시 발송만 제어한다. |
| NTF-08 | 알림 목록 | 수신한 알림을 시간순으로 확인한다. 종류에 따라 상태 색과 라벨이 구분되며 시각·정류장 등 맥락 정보를 함께 표시한다. 최근 14일까지 보관하고 끈 알림도 목록에는 남는다. 미읽음 건수는 헤더 배지로 표시한다. |
| NTF-09 | 팝업 알림 | 지연·미승차·노선 변경 같은 중요 알림은 목록 적재와 별도로 화면에 팝업으로 즉시 노출한다. 사용자가 앱을 보고 있는 중에도 놓치지 않게 하기 위한 것이다. |
| NTF-10 | 알림 수신 확인 관리 | 노선 변경·하차 위치 변경처럼 중요한 통지는 발송으로 끝내지 않고 수신자가 확인했는지까지 추적한다. 미확인 상태는 관계자 화면에 표시되어 전화 등 다른 수단으로 재차 안내할 수 있게 한다. |
| NTF-11 | 알림 로그 | 관계자가 보호자에게 전송된 모든 알림 내역을 조회한다. 시각·호차·대상·내용·종류·확인 여부를 표로 확인하며 미확인 건수는 내비게이션 배지로 표시한다. |

## 16. MON — 모니터링 (학원 관계자)

| 기능 코드 | 기능명 | 구체적인 설명 |
|---|---|---|
| MON-01 | 운행 관리 대시보드 | 오늘의 운행 상황을 한 화면에서 파악한다. 운행 중 차량 수, 승차 완료 인원, 미승차 인원, 배치 대기 매니저 수를 지표 카드로 표시하고 금일 운행 현황 표와 고정 노선 카드를 배치한다. |
| MON-02 | 금일 운행 현황 | 오늘 편성된 모든 회차를 표로 조회한다. 호차·구분·출발 시각·배치 인력·탑승 인원(현재/전체)·운행 상태를 표시하며 행을 누르면 해당 호차의 일일 탑승자 명단으로 이동한다. |
| MON-03 | 실시간 탑승 현황 | 운행 중인 회차의 승하차 처리 결과를 실시간으로 반영해 보여준다. 매니저 앱에서 상태를 변경하면 지연 없이 갱신되어야 한다. |
| MON-04 | 미승차 인원 확인 | 오늘 미승차로 처리된 학생을 모아 조회한다. 지표 카드로 건수를 노출하고 명단에서 상태 배지로 구분하며 대기·에스컬레이션 진행 상황을 함께 표시한다. |
| MON-05 | 당일 수정 노선 확인 | 확정 이후 변경된 내용을 확인한다. 추가된 탑승자는 초록, 삭제된 탑승자는 빨강으로 구분되며 어느 호차에서 무엇이 바뀌었는지 파악할 수 있다. **기사·인솔자의 변경 확인 응답 여부(RUN-07)도 함께 표시한다.** |
| MON-06 | 회차별 탑승 의사 확인 | 학부모가 설정한 회차별 버스 탑승 여부를 조회한다. 탑승 예정 인원과 미등원 인원을 집계해 오늘 실제 운송 규모를 파악한다. 학부모가 상태를 변경하면 관계자에게 통지된다. |
| MON-07 | 실시간 차량 위치 확인 | 운행 중인 전체 차량의 현재 위치를 지도에서 확인한다. 호차별 진행 상황과 지연 여부를 파악하는 용도다. |
