## 0. 왜 구현 후인가 (먼저 읽을 것)

`docs/` 4종은 **기획서가 아니라 실측 기록**이다. 특히 `PRODUCT_SPEC.md` §11 은 스스로를 이렇게 규정한다:

> *"이 장이 '지금 실제로 되는 것'의 유일한 근거다. 여기 없는 기능은 구현되지 않은 것이다."*

그래서 **구현 전에 ✅ 를 미리 적으면 그 자체가 허위**가 된다. 이 저장소는 이미 그 사고를 겪었다 —
`projectInfo.md` §3.1 이 "프론트엔드 MVP 데모에서 실제 화면으로 구현됨"이라고 적어 둔 화면들이 하나도 없어서,
`PRODUCT_SPEC.md` §0 이 그것을 **"흔한 오해"로 따로 경고**하고 있다. 같은 일을 반복하지 않는다.

⚠️ **`docs/plans/`(계획)와 `docs/`(사양)는 성격이 다르다.** 계획서는 구현이 끝나면 역할이 끝나지만
SoT 4종은 계속 유지된다. **계획서 내용을 사양으로 복사하지 마라** — 사양에는 "만들 것"이 아니라 "있는 것"만 적는다.

**공통 원칙**
- 표기는 `✅ 구현 / 🟡 부분 / ⬜ 미구현 / ➖ 범위 밖` 4개만 쓴다(`docs/README.md` §2)
- 모든 사실에 **파일 경로나 엔드포인트**를 붙인다. 근거 없는 서술을 두지 않는다
- 값(개수·수치)은 **추정하지 말고 실제로 세서** 적는다 — §5 에 세는 명령이 있다
- HTML(`docs/html/`)은 **자동 동기화하지 않는다.** 사용자가 따로 요청할 때만 손댄다

## 5. 실측에 쓰는 명령

수치를 **추정하지 말고** 아래로 센다. 결과가 계획서와 달라도 **실측이 이긴다.**

```bash
# 백엔드 REST 엔드포인트 수
grep -rEo '@(Get|Post|Put|Patch|Delete)Mapping' backend/src/main/java --include=*.java | wc -l

# 컨트롤러 수
find backend/src/main/java -name '*Controller.java' | wc -l

# 프론트 라우트 수 (AppRoutes 의 static const)
grep -cE '^\s*static const' frontend/lib/app/router/app_routes.dart

# 프론트가 실제 호출하는 엔드포인트 (중복 제거)
grep -rhoE "'/api/[^']+'" frontend/lib | sort -u | wc -l

# 엔티티 수
grep -rl '@Entity' backend/src/main/java | wc -l
```
