## 범위 — 기능 ID 와 엔드포인트

`RTE-02` · `RTE-08` · `RUN-01`. `ARCHITECTURE §9` 전체 + `§8.5` 배포·버전.

⚠ **이 Phase 의 산출물은 대부분 엔드포인트가 아니라 배치다.** 핸들러 수는 **분기점의 56 에서 늘지 않는 것이 기본값**이고, 늘린다면 그 근거를 목표 표에 먼저 적어야 한다.

**범위 밖으로 확정한 것**
- `POST /staff/routes/{id}/optimize` 의 **요청 본문 좌표를 선택으로 바꾸는 것** → 별도 단위(Ruling 190). 이번엔 필수를 유지한다
- ②구간 자동 거절 · 미승차 에스컬레이션 · 위치 유실 판정 → 각각 Phase 8·9·10 (`ARCHITECTURE §10` 폴링 표)
- 탑승 의사·변경 요청 → Phase 8

## 판정 규칙

1. **부분 통과는 완료가 아니다.** 13항 중 12항이면 🟡 로 남기고 미통과 항목을 함께 적는다. **다만 Ruling 189 대로 멈추지 않고 다음 Phase 로 가며, 미통과는 Phase 8 목표 표에 이월 등재한다**
2. **초록은 통과의 증거가 아니다.** 새 단언마다 음성 대조를 실측한다
3. ⚠ **이 Phase 의 목표 2·4·6 은 "설정은 있는데 안 밟힌다" 가 나오기 쉬운 자리다.** Phase 5·6 이 세 번 밟았다 — 재시도가 한 번도 안 걸림 · 격벽 거절 경로가 안 밟힘 · 선정 순서가 안 고정됨
4. ⚠ **음성 대조에는 구조적 사각지대가 있다**(Phase 6 T8 에서 처음 관측) — **변형은 밟히는 코드에만 효과가 있다.** "이 단언이 검사하려는 경로를 이 시험이 실제로 밟는가" 를 **먼저** 묻고, 안 밟으면 **밟게 만드는 것이 먼저**다
5. **`Clock` 빈 주입이 이 Phase 의 전제다**(`TECH_DECISIONS §6`). 시각을 주입하지 못하면 목표 1·3 을 검사할 수단 자체가 없다
6. ⚠ **테스트 클래스에 `@Transactional` 을 붙이면** 목표 2(동시 확정)가 원천적으로 검사되지 않는다 — **비트랜잭션 시험**이어야 한다
