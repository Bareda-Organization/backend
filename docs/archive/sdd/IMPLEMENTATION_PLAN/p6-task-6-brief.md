# Phase 6 태스크 6 — 동승자 자동 배정 (목표 9)

**선행: T4(파이프라인) 회수 완료.** ⑤는 ④의 `estDurationMin` 을 입력으로 받는다.

## 담당 목표 — **목표 9**

> 동승자 자동 배정이 근무 시간·중복 배치 충돌을 판정한다 (`ARCHITECTURE §8.2` ⑤, MGR-05·06).

## ⚠ 이름이 `BusAssigner` 가 아니다 — **`AttendantAssigner`** (Ruling 181)

`IMPLEMENTATION_PLAN` Phase 6 산출물 열이 옛날에 `BusAssigner` 로 적었으나 **설계 정본이 그것을 부정**한다.
`ARCHITECTURE §8.2` — "**파이프라인에 '학생을 버스에 배정하는 단계'가 부재**"
(학생↔버스 대응은 계산이 아니라 고정 노선 편성이 결정한다).
계약은 `p6-port-contracts.md §3` 이 정본이다.

## ⑤가 계산 **뒤에** 오는 이유

`ARCHITECTURE §8.2` — "동승자 배정은 **소요 시간이 확정된 뒤라야** 근무 시간 충돌을 판정 가능"
(`PRD §5.1` 2단계). 기사 배치는 그 전에 관계자가 수동으로 끝낸다.
**이 순서를 뒤집으면 `estDurationMin` 부재로 충돌 판정 자체가 성립하지 않는다.**

## 입력 — `manager.work_hours`

**Ruling 150** 이 형태를 고정했다(요일 키 × 구간 배열 × `HH:mm`). `progress.md` 에서 찾아 읽어라.
`PRD §10.1.1` 이 오픈 이슈 **K 를 폐기**했다 — "구조화된 시간 범위로 다루고 자유 텍스트를 두지 않음".
Phase 5 가 만든 `manager` 엔티티·저장소를 재사용하라. **새로 만들지 마라.**

## 판정 2종

| 사유 | 언제 |
|---|---|
| `OUT_OF_WORK_HOURS` | 회차 시간대(`departAt` ~ `departAt + estDurationMin`)가 근무 시간 밖 |
| `ALREADY_ASSIGNED` | 같은 시간대에 다른 회차에 이미 배정됨 (MGR-06 중복 배치) |

- ⚠ **경계 시각을 어떻게 볼지 정하고 단언으로 고정하라** — 근무 종료 시각과 회차 종료가 정확히
  같을 때 허용인가. 정본에 문언이 있는지 먼저 찾고, 없으면 정하고 **근거를 보고서 1항에 적어라**
- **후보 0명이면 `managerId=null` 로 돌려주고 예외를 던지지 마라.**
  자동 배정 실패가 노선 계산 전체를 무르면 안 된다 (`ARCHITECTURE §9.4` 회차 단위 격리와 같은 축)
- `rejections` 에 **왜 배정되지 않았는지**를 담는다 — 화면이 이유를 표시해야 관계자가 손으로 고칠 수 있다

## Phase 5 와의 경계

Phase 5 가 만든 `PATCH /staff/runs/{runId}/assignment`(MGR-05·06 **수동** 배치)와 **다른 것**이다.
Phase 5 목표 표가 "동승자 **자동** 배정(Phase 6)" 으로 명시해 갈라 뒀다.
**수동 배치 엔드포인트를 고치지 마라** — 고쳐야 한다고 판단하면 `BLOCKED` 로 보고하라.

## ⚠ 이 Phase 가 실제로 밟은 함정 5가지 — 그대로 적용하라

Phase 6 T1~T5 에서 **리뷰가 잡았거나 사고로 이어진 것**만 추렸다. 추상론이 아니다.

1. **"여러 개 있으니 잡히겠지" 가 두 번 틀렸다.**
   T2 는 단언 3개인데 **좌표 배치** 때문에 변형에 1개만 물었고, T5 는 가드 2개인데
   **앞 가드(개수 대조)가 뒤 가드를 가려** 변형이 살아남았다.
   ⇒ **변형을 심고 몇 건이 실패하는지 세라.** 개수가 예상과 다르면 그 자리를 파라
2. **`git add` 부분 실패로 한 라운드 작업이 통째로 사라졌다.**
   `git add A B` 에서 B 가 없으면 **exit 128 이고 A 도 안 담긴다.** `git status --short` 의
   **`RM` 은 "rename 은 담겼고 수정분은 아직" 이라는 뜻**이다("둘 다 됨" 이 아니다).
   ⇒ **스테이징 확인은 `git diff --cached` 로**, 커밋 후 **`git show --stat` 의 `insertions` 가 0 이 아닌지**.
   `git add` 에 **`2>/dev/null` 을 붙이지 마라**. 전문은 `~/.claude/rules/parallel-agents-git.md §1.1`
3. **원복 스크립트가 다른 인스턴스 블록을 바꿔 "거짓으로 잡혔다" 가 나왔다.**
   ⇒ **변형 1회 = 원복 1회 = `git status --porcelain` 확인 1회**를 묶어서 돈다.
   마지막에 한 번 확인하면 **어느 회차가 오염됐는지 가릴 수 없다**
4. **"규약이라 어쩔 수 없다" 는 옮겨서 돌려 보면 판정된다.** T1 이 Spring Data 조각 배치를
   그렇게 주장했고 세 좌석이 세 번 갈린 끝에 실측으로 결론이 났다.
   ⇒ **제약을 주장하기 전에 시험하라.** 그리고 **"가능하다" 와 "규약이 그렇게 하라고 한다" 는 다른 물음**이다
5. **동시성 시험은 시간 기반 `sleep` 을 쓰지 마라.** T5 가
   **`pg_stat_activity.wait_event_type='Lock'` 폴링**으로 결정적 순서를 만들었고 리뷰가
   "이 저장소의 플레이키 문제를 실제로 해결" 로 평가했다. **네 태스크에 동시성 축이 있으면 그 방식을 따르라**

## 조율자 판정 — 알고 있어야 할 것 2건

1. **Ruling 184** — `optimize` 는 좌표를 **요청 본문으로 받는다**(`academy`·`route` 에 좌표 컬럼 부재).
   네 `AttendantAssignInput` 은 좌표를 안 받지만, **`estDurationMin` 이 그 계산의 산물**이라
   간접적으로 얽힌다. 계약을 바꿔야 하면 `BLOCKED`
2. **`BusinessException(code, message)` 의 message 는 응답에 도달하지 않는다**(저장소 전역 성질).
   ⇒ **오류 사유를 문구로 가르지 마라.** 갈라야 하면 `ErrorCode` 를 나누거나 응답 본문 필드로 실어라.
   T5 의 가드 가림이 정확히 이것 때문이었다

## 음성 대조 (커밋 후)
- 근무 시간 검사를 **조용히 통과**(항상 true) → `OUT_OF_WORK_HOURS` 단언만 실패
- 중복 배치 검사에서 **시간대 겹침 조건을 제거**(같은 날이면 무조건 충돌 → 범위 한 칸 넓히기)

- `estDurationMin` 을 **무시**(회차 시작 시각만으로 판정) → 소요 시간 축 단언만 실패
