이 폴더가 단일 소스(SoT)다

아래 4개 문서가 백엔드·프론트엔드를 아우르는 상위 계약이다. 각 모듈의 심화 문서는 여기에 종속되며, 사실이 어긋나면 이쪽이 기준이다. 원본은 저장소의 docs/*.md 이고 이 HTML은 같은 내용의 렌더다.

1. 문서 4종

제품 사양서

서비스 목적 · 사용자 계층 · 도메인 데이터 · 배차 · 승하차 · 예외 · 알림 정책 · 법적 요건 · 로드맵 + MVP 구현 범위 매트릭스 · 미구현 갭 목록

유저플로우

역할별 진입 지도 + 플로우별 “행동 → 화면 → API → 결과” 추적. A부 구현됨 / B부 설계됨·미구현 으로 분리

아키텍처

백엔드 모듈 구조 · 프론트 레이어 · 인증인가 · 멀티테넌시 · 데이터 모델 · 실시간 파이프라인 · 비동기 · 인프라 + 아키텍처 리스크

API 명세서

전체 엔드포인트(권한 · 테넌트 격리 · 구현 상태 · 프론트 사용 여부) + 공통 규약 · enum 사전 · WebSocket

처음 보는 경우 읽는 순서: 제품 사양서 → 유저플로우 → 아키텍처 → API 명세서

2. 지금 상태

MVP는 기사 앱 + 관리자 웹까지 동작하고, 학생·학부모 앱은 화면이 없다.

역할정의화면상태
운전기사 DRIVER✔2 — 오늘의 노선 · 승하차 명단구현
학원 관리자 ACADEMY_ADMIN✔4 — 관제 · 배차 · 노선 · 알림구현
플랫폼 관리자 PLATFORM_ADMIN✔4 — 학원 관리자와 동일*부분
학생 STUDENT✔0 — 로그인 후 “준비 중” 배너미구현
학부모 PARENT✔0 — 로그인 후 “준비 중” 배너미구현

* 화면 구성은 같고 tenant 결정 방식만 다르다 — 학원 관리자는 JWT 고정, 플랫폼 관리자는 드롭다운 선택.

백엔드가 앞서 있다

SOS · 결석 신고 · 일정 변경 · 버스/학생/회원 등록 · 승하차 정정은 백엔드에 이미 구현돼 있으나 프론트가 호출하지 않는다. 미승차·근접·SOS 에스컬레이션 자동 판정도 스케줄러로 실제 동작하지만, 그 결과를 볼 화면이 없다. 새 기능을 만들기 전에 API 명세서 부록 A 매트릭스에서 이미 있는지 확인할 것.

3. 표기 규칙

문서 전반에서 구현 상태를 아래 4개 기호로만 표시한다. 기획된 것과 구현된 것을 반드시 가른다.

기호뜻
✅ 구현실제 동작한다
🟡 부분동작하나 하드코딩 · Mock · 제약이 섞여 있다
⬜ 미구현설계 · 기획만 있다
➖ 범위 밖MVP 대상이 아니다

⚠ 는 함정·리스크, ※ 미확인: 은 조사 범위에서 확인하지 못한 항목이다. 근거 없는 서술을 두지 않는다 — 사실에는 파일 경로나 엔드포인트가 붙는다.

📊 기능은 있는데 볼 화면이 없다 — 데이터 흐름의 종착점 부재

6. 문서 포맷 규칙

  • 저장소의 docs/*.md 4종이 원본이다. 이 html/ 은 같은 내용의 사람용 렌더다.
  • 원본을 고쳤다고 HTML을 자동 동기화하지 않는다 — 필요하면 별도로 요청한다.
  • Claude가 매 세션 재참조하는 문서는 토큰 효율을 위해 Markdown으로 유지한다.
  • 이 HTML 5종은 assets/sketch.css 를 공유한다. 색·간격을 바꿀 일이 있으면 그 파일만 고친다.
