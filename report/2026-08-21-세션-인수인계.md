## 3. 재개 시 반드시 알아야 할 사실

### 3.1 상태 모델은 기획 문서가 정본이다

`docs/brainstorming/` 의 **PRD·기능정의서**(2026-08-21 추가)가 상태 5종을 확정 정책으로 못박는다 — `waiting`·`boarded`·`alighted`·**`absent`**·`no_show`.

⚠ **`absent ≠ no_show` 는 확정 정책이다.**
- `absent` = 학부모가 **사전** OFF → **학부모 알림 없음**, 관계자만 통지
- `no_show` = **현장** 미승차 → **즉시 알림 + 3분 에스컬레이션**

**둘을 섞으면 이미 "안 탄다"고 알린 학부모에게 관리자가 전화한다.**

### 3.2 `ABSENT` 는 호출부가 조회해 넘겨야 한다 — 조용히 실패한다

`BoardingStatusResolver.resolve()` 가 `approvedAbsenceToday` 를 **인자로 받는다.**
호출부가 안 넘기면(하드코딩 `false`) **컴파일도 되고 테스트도 통과하는데 `ABSENT` 가 영원히 안 나온다.**
Task 3(`OperationsQueryService`)이 올바른 방식을 보여준다 — `attendanceExceptionRepository` 학원 전체 1회 조회 → `APPROVED` + 당일 필터 → 학생 id Set.

### 3.3 임계값은 `NotificationThresholds.NO_SHOW`(10분)를 쓴다

임의 값을 넘기면 **화면과 알림이 서로 다른 기준으로 "누락"을 말한다.**

### 3.4 기획이 전제하나 현재 코드에 없는 것 (설계 §5.4)

**"구현됨"으로 적지 말 것.** 회차(run) 자동생성 · 3구간 규칙(60분) · 미경유(skipped) 정류장 · **기사·인솔자 변경 확인 응답(RUN-07)** · 탑승 의사 토글.
특히 RUN-07 은 MON-05 의 절반인데 **대응 엔티티·API 가 전무**하다 — 빈 필드를 만들지 말고 미구현으로 남긴다.

### 3.5 로컬 환경 함정

- **`curl localhost:8080` 안 된다.** backend 는 `expose` 만 쓰고 `ports` 가 없다. `proxy`(:80)도 기본 기동 대상이 아니다.
  → 컨테이너 안에서: `docker compose exec -T prometheus wget -qO- http://backend:8080/...`
- **`application.yml` 은 이미지에 구워진다.** 설정만 고치고 `restart` 하면 반영 안 됨 — `up -d --build backend` 필요.
- **동시 에이전트 2개까지.** 4개 돌렸을 때 부하로 **postgres 가 크래시**해 Spring 컨텍스트 테스트 9개가 실패했다(코드 결함 아님).
- **`docker compose down` 금지**(`-v` 는 더더욱). 현재 컨테이너 9개 기동 중.
