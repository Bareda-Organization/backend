## 5. ⚠ 다음 Phase 가 반드시 지킬 것 3가지 — Phase 6 이 값을 치르고 얻었다

### ① 음성 대조에는 **구조적 사각지대**가 있다

**변형은 밟히는 코드에만 효과가 있다.** Phase 6 목표 5-a 의 시험은 게이트 리뷰 2회를 통과했으나
**격벽이 포화되지 않으면 폴백 경로 자체를 안 밟아** 실 결함을 못 봤다. 무엇을 심어도 안 잡힌다.

⇒ **"이 시험이 그 경로를 실제로 밟는가" 를 먼저 묻는다.** 안 밟으면 **밟게 만드는 것이 먼저**다.

### ② **"단언은 있는데 안 문다" 가 다섯 번 났고 매번 형태가 달랐다**

①좌표 배치로 3개 중 1개만 물음 ②앞 가드가 뒤를 가림 ③시험이 행을 순번대로 넣어 `ORDER BY` 가 헛돎
④그 축을 겨냥한 시험이 아예 부재 ⑤경로 자체를 안 밟음.

**다섯 번 다 판별 수단은 변형을 심어 실패 건수를 세는 것 하나뿐이었다.**

### ③ **브리프에 "정본은 X 다, 직접 대조하고 어긋나면 보고하라" 를 실어라**

Phase 6 에서 **조율자 오기 2건**(포트 계약 enum 2값 · 브리프의 503 요구)을 **아래 사람이 정본을 읽어 잡았다.**
둘 다 **정본을 grep 하지 않고 기억으로 적은 것**이 원인이다. 이 장치가 실제로 두 번 작동했다.

⚠ **포트 계약에 enum 을 새로 적을 때는 그 개념의 기존 코드값(`*WarningCode`·`ErrorCode`)을 먼저 grep 한다.**

## 6. 환경 — 다음 세션이 반드시 알아야 할 것

### ⚠ postgres 서버 프로세스가 죽어도 `docker ps` 에는 흔적이 없다

이 세션에서 실제로 발생했다. **컨테이너 재시작 0회 · `OOMKilled=false` · 상태 `healthy`** 인데
로그에는 `server process exited with exit code 2` → `reinitializing` → `FATAL: ... recovery mode` 가 남았다.

**테스트 실행 전후로 이것을 세라.**

```bash
docker logs school-bus-postgres-1 --tail 200 2>&1 | grep -icE 'reinitializing|recovery mode|exited with exit code'
```

값이 늘었으면 **그 실행의 실패 목록은 증거 능력이 부재**하다. 안 보면 환경 문제를 코드 결함으로 적게 된다.

### 호스트 메모리가 병목이다

**16GB 머신인데 여유가 80~200MB** 이고 swapout 이 난다. 다른 앱이 6GB 가까이 쓴다.

- **테스트 워커 힙은 `1024m` 로 고정**됐다(`build.gradle`, Ruling 188). **기본값은 512m** 이고 묶음이 커지며 부족해졌다
- 워커 실제 상한 확인 — `./gradlew test --tests '<하나>' --info | grep -oE '\-Xmx[0-9a-zA-Z]+'`
- **`maxParallelForks` 를 늘리지 마라.** **동시 좌석도 적게** — 크래시는 좌석 2개 + 호스트 압박에서 났다

### 그대로 둔 것 / 정리한 것

- **Docker 는 켜 둔 채로 둔다**(`postgres`·`redis`·`kafka`). `docker compose down` 을 하지 않았다
- **워크트리 0개 · Phase 6 브랜치 11개 전부 병합 확인**(`git merge-base --is-ancestor`). 브랜치는 보존
- ⚠ **테스트 DB 가 45개 넘게 쌓여 있다**(`schoolbus_*` · `p6t6` · `p6t7` · `p6t8` · `p6final` · `p6final2` 등).
  **지우지 않았다** — DROP 은 파괴적이라 사용자 확인 없이 하지 않는다. 정리하려면 확인을 받고 한다
- `caffeinate` 는 **켜 둔 채다**(다음 세션이 에이전트를 띄운다). 끄려면 `pkill caffeinate`
