## 전역 제약

- Java 25(toolchain 고정) · Spring Boot 4.1.0 · Gradle. 웹 스타터는 `spring-boot-starter-webmvc`(테스트 `spring-boot-starter-webmvc-test`) — 구버전 `spring-boot-starter-web` 아님.
- 모든 클래스는 `src.backend.*` 하위(컴포넌트 스캔 범위). `package-info.java` 를 만들지 않는다.
- service·repository 의 `spec`/`impl` 분리는 **"구현이 바뀔 가능성이 있는가"** 일 때만. 이 문서가 건드리는 서비스는 전부 단순 CRUD·조회라 **concrete 클래스 그대로** 둔다(리포지토리 인터페이스는 기존대로 `repository/spec/`).
- 모든 gradle 명령은 **`backend/` 에서** 실행한다. `ddl-auto: validate` 를 **유지**한다 [OVERVIEW D-E] — 엔티티 필드와 DDL 은 같은 커밋에서 맞춘다.
- 커밋 메시지는 저장소 관례인 **모듈 스코프**(`feat(bus):`, `fix(auth):`), 본문은 한국어.

## BE-1: 스키마·시드 확장

**목적:** 선탑자·사진·전화·위치변경요청을 담을 컬럼과 데모 데이터를 만든다.
**선행:** —

**Files:**
- Modify: `backend/src/main/resources/db/migration/V1__init_schema.sql` — `app_user.photo_url` / `student.photo_url`·`phone` / `bus.attendant_id`+FK / `user_tenant_role.role` CHECK / `location_change_request` 신규 테이블
- Modify: `backend/src/main/resources/db/migration/V5__notification_log_add_route_published_type.sql` — `type` CHECK 에 `'LOCATION_CHANGE_RESULT'`
- Modify: `backend/src/main/resources/db/migration-local/V2__seed_data.sql` — 선탑자 3명·`ATTENDANT` 역할·버스 3대 `attendant_id`·사진/전화
- Test: 없음(스키마 검증은 앱 기동 + Flyway 로 한다)

**Interfaces:**
- Consumes: —
- Produces: 컬럼 `app_user.photo_url`, `student.photo_url`·`student.phone`, `student.pickup_lat`·`pickup_lng`·`pickup_address`(D-K), `bus.attendant_id`(nullable bigint → `app_user.id`), `user_tenant_role.role in (…,'ATTENDANT')`, 테이블 `location_change_request`. `BE-2` 가 여기에 엔티티 필드를 맞춘다.

⚠️ **새 마이그레이션(V6…)을 만들지 않는다** [OVERVIEW D-D]. `V1` 을 직접 고친다. `V3`·`V4` 는 건드리지 않는다.
⚠️ `V1` 은 Hibernate 생성 DDL 스타일이다 — **들여쓰기 4칸, 전부 소문자, 컬럼은 타입 그룹별 알파벳 순**. 그대로 지킨다.

- [ ] **Step 1: `V1` 컬럼 삽입** — 각 `create table` 안, 지정한 줄 **바로 다음**에 넣는다. Hibernate DDL 은 타입 그룹(float → bigint/timestamp → varchar)별 알파벳 순이라 삽입 위치가 그룹마다 다르다.
  | 테이블 | 이 줄 다음에 | 넣을 줄 |
  |---|---|---|
  | `app_user` | `phone varchar(255),` | `photo_url varchar(255),` |
  | `bus` | `seat_capacity integer not null,` | `attendant_id bigint,` |
  | `student` | `dropoff_lng float(53),` | `pickup_lat float(53),` 와 `pickup_lng float(53),` |
  | `student` | `name varchar(255) not null,` | `phone varchar(255),` · `photo_url varchar(255),` · `pickup_address varchar(255),` |

  `bus.attendant_id` 는 bigint 그룹의 첫 줄(= `created_at` 앞)이 된다. **NOT NULL 을 걸지 않는다** — 버스 생성 API 가 선탑자 없이도 생성 가능해야 한다 [OVERVIEW I-1].
  `student` 의 `pickup_*` 3컬럼은 기존 `dropoff_lat`/`dropoff_lng`/`dropoff_address` 와 **나란한 형태**다(전부 nullable). 등원 좌표를 학생 자신이 갖게 하는 것이 목적이다 [OVERVIEW D-K] — 아래 **PICKUP 좌표 우선순위 규칙** 참조.

> **PICKUP 좌표 우선순위 규칙 (D-K)** — 이 컬럼들의 의미를 정의하는 규칙이다.
> 1. `pickupLat`·`pickupLng` 가 **둘 다 있으면 그 좌표를 쓴다.**
> 2. 없으면 `boardingStop.lat/lng` 를 쓴다.
> 3. 둘 다 없으면 그 학생은 **해당 노선 계산에서 제외**한다.
>
> `boardingStop` 은 여러 학생이 공유하는 `Stop` 이라 학부모 한 명의 위치 변경이 같은 정류장의 다른 학생까지 움직인다 — 그래서 학생별 좌표를 따로 둔다. 이 규칙의 **구현은 `BE-4`(`RoutePlanComputer.pointOf`)** 가 하고, `BE-10`(학부모 위치 변경)이 `pickup_*` 을 갱신한다. 컬럼을 만드는 이 문서에 규칙 원문을 남겨 둔다.

**검증:**
1. ⚠️ **Docker 는 에이전트가 직접 실행하지 않는다.** 아래를 **사용자에게 실행 요청**한다(저장소 규칙).
   ```bash
   docker compose down
   docker compose up -d postgres redis kafka
   ```
   `stop`/`start` 로는 안 된다 — `V1` 체크섬이 바뀌어 기존 볼륨이 남으면 Flyway validation 실패로 앱이 뜨지 않는다.

1. **`BusResponse` 에 `attendantId` 를 넣지 않았다.** 응답에 선탑자 정보가 필요하면 `BE-6`(버스 상세 종합 응답)에서 확장한다 — P1 에서 DTO 를 건드리면 `BE-6` 과 충돌한다.
2. **시드 계정 이메일·사진 URL 은 이 문서에서 정했다**(OVERVIEW 에 규정 없음). 프론트(`FE-1`·`FE-4`)가 데모 계정을 문서화할 때 `attendant3@school.com` 을 기준으로 삼는다.
3. **한 사람이 기사이자 선탑자인 경우는 없다고 가정**했다(`getMyBus` 가 기사 배정을 우선한다). 시드가 이를 지킨다.
4. **`GET /api/drive-sessions/bus/{busId}` 는 [OVERVIEW §4.1] 사슬에 따라 열었다.** 초안에서는 "권한표에 없으니 기사 전용" 으로 남겼으나, 이것이 선탑자에게 **세션 id 를 주는 유일한 경로**라 빼면 `/roster` 를 열어줘도 명단 화면이 통째로 뜨지 않는다. Step 8·9 에서 컨트롤러와 서비스 인가를 함께 확장한다.
5. **`SignupRequest.tenantId` 에 `@NotNull` 을 붙였다.** 누락 시 서비스의 `INVALID_INPUT` 대신 bean validation 이 먼저 잡지만 상태 코드는 400 으로 동일하다.
