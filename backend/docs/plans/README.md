### 실행 순서

```
BE-11 ─────────────────────────────────────────────┐ (독립, 언제든)
BE-1 → BE-2 → BE-3                                 │
              ├→ BE-4 → BE-5                       │
              ├→ BE-6 → BE-13                      ├→ 문서 갱신(DOC-*)
              ├→ BE-7 ──┐                          │
              ├→ BE-12 ─┴→ BE-14                   │
              └→ BE-8 → BE-9                       │
                 BE-4 + BE-1 → BE-10 ──────────────┘
```

**순차 강제 3쌍** — 같은 파일을 고쳐서다. 병렬로 돌리면 충돌한다.

| 먼저 | 다음 | 겹치는 파일 |
|---|---|---|
| `BE-5` | `BE-10` | `routing/command/RoutingCommandService.java` |
| `BE-6` | `BE-13` | `student/repository/spec/StudentRepository.java` |
| `BE-7` · `BE-12` | `BE-14` | `bus/command/BusCommandService.java` · `user/controller/MemberController.java` |

### ⚠️ 이 확장에서 반드시 지킬 것

- **`V1__init_schema.sql` 을 직접 수정한다.** 새 마이그레이션(V6…)을 만들지 않는다 → 반영하려면 `docker compose down` 후 `up`. `stop`/`start` 는 Flyway 체크섬 검증에 걸려 앱이 뜨지 않는다.
- **Docker 는 직접 실행하지 않는다.** 사용자에게 요청한다.
- **기사에게서 뺏는 것은 기록 권한뿐이다.** 운행 세션 시작·종료와 버스 위치 보고는 `DRIVER` 유지.
- **시뮬레이션은 어떤 행도 저장하지 않는다.** 저장은 `apply` 계열에서만.
- **`DELETE` 는 물리 삭제가 아니다**(D-O). 구성원은 학원 멤버십 해제, 학생은 `active=false`. `app_user`·`student` 행은 지우지 않는다 — 승하차 기록이 참조한다.
- **기사↔선탑자 매칭 전용 API 를 만들지 않는다**(D-P). 둘을 잇는 유일한 매개는 `Bus.driver` + `Bus.attendant` 다.
