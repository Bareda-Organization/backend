# MVP API 명세서 — `docs/API_SPEC.md` 로 이관됨

> 이 문서의 내용은 저장소 루트 **[`docs/API_SPEC.md`](../../docs/API_SPEC.md)** 로 흡수·확장됐다.
> 이 파일은 링크만 남긴 stub 이다. 원본 내용은 git 이력에서 확인할 수 있다.

## 왜 옮겼나

이 문서는 "**MVP 화면이 실제로 호출하는 API 18개**"만 다뤘다. 범위를 좁게 잡은 것 자체는 합리적이었으나
운영하면서 두 가지 문제가 생겼다.

1. **드리프트.** 코드가 앞서 나가면서 문서가 뒤처졌다 — 실측 결과 프론트가 호출하는 REST 엔드포인트는
   18개가 아니라 **22개**였다. 이 문서를 검증한 보고서가 `backend/report/` 에 두 번(2026-07-28) 쌓인 이력이 있다.
2. **경계.** "MVP에서 쓰는 것"만 적혀 있어서, **백엔드에는 있는데 프론트가 아직 안 쓰는 기능**이 문서에서
   보이지 않았다. SOS·결석신고·일정변경·기초데이터 관리가 여기 해당한다. 프론트를 붙일 때 무엇이 이미
   준비돼 있는지 알 수 없는 상태였다.

## 무엇이 달라졌나

새 `docs/API_SPEC.md` 는 **전체 API 표면**을 다루되, 엔드포인트마다 다음을 명시한다.

- **프론트 사용 여부** — `✅프론트 사용` / `⬜프론트 미사용` 배지. 부록 A의 매트릭스만 봐도
  "백엔드에만 있는 기능"이 한눈에 보인다.
- **권한** — `@PreAuthorize` 원문 또는 SecurityConfig 경로 규칙
- **테넌트 격리** — 어디서 검증하는가. **검증이 없으면 `검증 없음 ⚠` 로 표시**한다.
- **구현 상태** — `✅ 구현 / 🟡 부분 / ⬜ 스텁`

또 이 문서에 없던 것이 추가됐다: 전역 공통 규약(응답 래퍼·에러 코드 전체·페이징·날짜 직렬화),
enum 값 사전, WebSocket 구독 권한 검증, 테스트 계정·시드 데이터.

## Swagger UI

앱 기동 후 `http://localhost:8080/swagger-ui/index.html` 의 **"00. MVP 사용 API"** 그룹은 그대로 유효하다.
단 이 그룹의 태그가 붙은 엔드포인트와 프론트가 실제 호출하는 엔드포인트는 **완전히 일치하지 않는다** —
차이는 `docs/API_SPEC.md` 부록 A 매트릭스에 정리돼 있다.
